2026-11-16。只验独立 Compare 路径，不用此前聊天侧跨论文回答代替。本轮由用户委托代理对照原文裁决，以语义、对象和条件正确为准，接受忠实转述，不要求所有结论都人工入库。

## 固定范围

从知识库勾选两篇 → 独立对比 → 当前原文与论文归属检查 → 现有机器辅助复核 → 表格与来源右栏 → 受托核对一条 → 保存/预览/导出 → 来源回收后的导出约束。

复用此前公开论文的已冻结材料，不新下载、不新提取。证据根为 `_selftest.n04-compare-20261116/`；源为 `_selftest.n04-retrieval-live-20261025/`，以只读连接和 SQLite online backup 取得新隔离副本。保留库中另外两篇作为未选来源对照，禁止送入模型；当前原文与材料 ID、块内容、源清单和实现哈希存于 `live/sources.json` / `live/manifest.json`。

实际入口是默认知识库勾选对比，不为模型额外注入预期答案。核对目标是架构、训练目标/使用方式及任务评价归属：Transformer encoder-decoder 与 BERT encoder、翻译自回归目标与 MLM/NSP 预训练和下游适配应区分；不同数据/任务上的分数不能直接排名。`aspects` 参数另以离线 API 控制验证，不因默认界面没有维度配置而新增配置项。

真实调用固定一次 `compare`，以及既有流程按窗口和内容组织的 `semantic_review` / `semantic_cross_review`；只使用已授权服务与模型，不搜索、不重新解读、不追加聊天或自动重发。1M/384K 能力与自动输出分配保持，不新增产品调用预算或输出上限。独立 Compare 仍走普通任务，不据此声称已获得 N01/Web QA 同等跨重启持久恢复。

## 离线反例与本轮修复

新增 `tests/test_compare_entry.py`，9 个案例串联实际 API 与 CompareAgent。改前 **6 失败、3 通过**，暴露以下四类问题；原始日志保留。

| 问题 | 改前行为 | 修复与验证 |
|---|---|---|
| 有效选择中夹带无效论文 | 两篇有效论文加未知 ID 仍生成，实际范围被静默缩小 | 任一无法识别的选择先报错，不发模型请求 |
| 同篇不同别名/重复选择 | 同一 ID 与标题可被当成两篇；重复输入重复送原文并创建 D3 | 按解析后的论文 ID 去重并保留首次顺序，至少两篇不同论文 |
| 对比维度结构异常 | 非对象条目或非字典 `values` 被标错后继续进入字段遍历，导致接口异常 | 记录结构问题并排除无效条目；返回明确的受阻结果，不以 500 或正常表格展示 |
| 生成期间材料换版 | 历史块本身仍存在，旧结论可能以当前结果展示 | 机器复核前、完成后及保存快照事务内核对当前材料；换版阻止正常发布，且不继续为过期材料发起机器复核 |

正向控制验证 `aspects` 传入、顺序稳定、仅选中当前原文、不读旧分析；负向控制验证单元格跨论文引用不放行。这里只检查可确定的来源/结构问题，不增加自动语义判分或要求逐字一致。

修复位于 `agents.py:CompareAgent` 和 `comparison.py`，不改变通用历史引用回溯规则，不删除旧材料，也不放宽已有机器或人工来源边界。
