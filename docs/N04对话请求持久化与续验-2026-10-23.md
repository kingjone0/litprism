# N04 对话请求持久化与显式续验

更新：2026-10-28。实现范围为持久Web对话入口，已接G05a流式草稿；旧消息不反向补建为完整请求。早期日期的验收结果保留，当前验证和后续队列以状态页/实施计划为准。

## G05a真实流式与发布边界

新Web聊天的QA生成通过真实SSE读取OpenAI兼容协议或Anthropic Messages的增量；查询扩展和其他工具仍沿原路径。服务端只从结构化JSON的根answer或answer_units各项text提取草稿，不把question_items、quotes、subject等元数据当正文。跨帧UTF-8、JSON转义/Unicode和单元边界单独处理，原始完整响应仍走原解析/对应/引用与版本校验，不用临时草稿重建正式回答。

服务提供的reasoning_content/reasoning或thinking增量单独显示；无实际字段不虚构思考。最终用量按服务报告记录；OpenAI终块usage和Anthropic累计usage按对应协议读取，不重复相加。未正常结束、达到输出上限或服务报错不能发布完整回复，失败/未知尝试保留，不自动换非流式请求重发。

`GET /api/chat-runs/{rid}/events` 是带既有token守卫的只读SSE订阅，返回run_id、阶段、增量和终态；首次/重连用reset快照，后续增量避免重复追加，heartbeat保持连接。读取、重连或刷新从不新建模型请求；生成POST、显式未知重试和成功精确复用的原契约保持。当前两协议客户端接真实增量；显式mock/仅实现旧接口的扩展客户端仍等待完整结果，不模拟打字或伪造流式。

临时内容仅在当前进程的有界运行缓存和浏览器内存中，不写messages/知识/上下文摘要/正式导出。页面刷新可重新订阅仍在运行的请求；**后台进程重启不保留未完成草稿**，原started/未知调用仍通过持久记录明确续验，不重新生成。已存完整响应、用量与最终消息仍按原事务持久化和N08备份；无需schema迁移，仍v15。

完成后预览被当前校验结果替换；拒答/错引用等隔离结果不得继续冒充正常答案，来源失效/材料换版守卫保留。断流/取消显示未完成草稿，不能整理成可信知识；切会话/旧帧/延迟完成不得覆盖当前会话。用户读到末尾时跟随新增正文，上翻后不强制滚动；窄屏停止按钮至少44px。正常生成的审计记录默认收起，用户手动展开状态保留，失败/中断仍主动显示待处理记录。

协议参考：[OpenAI Chat Completions增量事件](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)、[Anthropic流式消息](https://platform.claude.com/docs/en/build-with-claude/streaming)。本机两协议/真实服务的小范围验证不等于所有代理兼容、服务可靠率或学术质量保证。

## 用户流程

新问题提交时生成稳定请求标识，先保存用户消息、当时范围和恢复绑定，再排队执行。界面的“本轮请求记录”可在刷新或重新打开会话后查看。相同标识只领取原记录，不能改成另一个问题；重复领取或查看结果不会调用模型。

```mermaid
flowchart TD
    Q[问题和稳定请求标识] --> R[保存请求与用户消息]
    R --> J[调用前登记尝试]
    J --> M[单次服务请求]
    M --> S[先保存响应和用量]
    S --> G[引用与来源守卫]
    G --> P[同一事务保存回复 审核快照 已发布结果]
    J --> U[失败或中断 结果与费用可能未知]
    U --> H{用户选择}
    H -->|结束请求| END[保留记录 允许另行提问]
    H -->|明确重新请求| B{来源 模型 历史 实现一致}
    B -->|否| NEW[要求依据当前材料重新提问]
    B -->|是| REUSE[完全匹配的成功响应直接复用]
    REUSE --> RETRY[仅未成功的尝试再次请求]
    RETRY --> S
```

已保存响应但尚未发布时，可“继续处理已存请求”；成功响应精确复用，不重复计入新调用。失败或只有发送登记的尝试必须明确选择“重新请求（可能再次计费）”。原失败、未知尝试和用量永久保留，不改写成新成功。

查看状态只投影“执行已中断”，不修改数据库。尚在执行时使用任务取消；没有执行者的未完成请求可以“结束此请求”，结束不证明服务没有计费，也不删除响应。取消发生在收到响应之后时，响应仍可保存供续验使用。

## 数据与恢复约束

schema **v14** 新增 `chat_runs` 和 `chat_run_calls`。前者保存请求标识、原问题/范围、用户消息、绑定哈希、运行状态和已发布结果；后者逐次保存逻辑阶段、精确请求哈希/内容、尝试序号、响应及独立思考、数值用量、安全参数和异常类别。它们在本机数据库中，不出现在状态接口正文或 Git；密钥、请求头、原始异常正文和服务 URL不写入调用诊断。独立思考只恢复作展示，不成为来源或下一轮事实。

调用前的登记是发送意图，不证明数据已到达服务；崩溃时按结果/费用未知处理。服务未上报用量不当作零费用。模型用量覆盖查询扩展和 QA；网页搜索另留阶段记录，不将网页服务次数算成模型 token。

恢复绑定包括当前范围、论文当前材料及可信状态/原文、人工知识快照及片段、此前历史和当前会话尾部、偏好、审核与压缩状态、模型/协议/参数、上下文/检索配置和实现哈希。新问题、材料换版、来源撤销或修改、模型切换、相关状态变化会阻止旧请求恢复。当前采用保守绑定，其他论文或审核变化也可能要求重新提问；不提供跨版本自动接续。

每次调用前和发布前重新核对绑定；请求级文件锁防止同一请求重复执行。持久路径关闭客户端隐式传输重试和 QA 超窗重发；不增加手工调用额度、输出额度或窗口配置。更换上游结果后若下游请求不再与已有记录一致，拒绝复用并要求新问题，不猜测缓存适用性。

回复、`qr_`人工审核快照和已发布结果在同一数据库事务提交；发布后的整理失败不把已发布记录降级为失败。结果重新读取时从原消息取回并重新检查来源/人工审核状态，不直接展示已失效的缓存答案。

## API

| API | 行为 |
|---|---|
| `POST /api/conversations/{cid}/chat-runs` | 创建或领取同一请求；字段 `request_id/question/top_k/web_search` |
| `GET /api/conversations/{cid}/chat-runs` | 最近30项；读取不调用模型 |
| `GET /api/chat-runs/{rid}` | 运行与各次安全状态、用量、是否需明确重试 |
| `GET /api/chat-runs/{rid}/result` | 已发布结果；读取当前消息与来源状态，不初始化模型/凭据 |
| `POST /api/chat-runs/{rid}/resume` | 未成功尝试须传 `retry_failed=true`；已发布请求不会重发 |
| `POST /api/chat-runs/{rid}/stop` | 结束没有执行者的未完成请求，保留调用历史 |

旧 `/api/chat/{cid}` 和通用 tasks 的旧 chat 操作保留兼容，不自动获得持久恢复；当前聊天界面已经使用新入口。旧单篇分析/对比/Skill/CLI/MCP的边界分别按各自契约判断。
