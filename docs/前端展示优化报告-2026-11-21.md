## 二、批次执行过程与关键排障经验

1. **V1 地基与图标（`2b92ab3`）**：
   - 建立设计 token 与基线对比截图集（`_selftest.uipolish-20261121/baseline/`）。
   - 契约测试 16 项全部通过。
2. **V2 功能入口清晰化（`07b1c94`）**：
   - 完成动作分组、占用入口常显化与空态统一。
   - 契约测试通过，验证截图正常。
3. **V3 降噪与排版层级（`b4e59e4`）**：
   - 落地 `run-detail` 折叠条、`cite-chip` 渲染、toast 样式柔化与文献列表多层化。
4. **V4 轻量动效与排障（`ce5a501`）**：
   - **View Transitions API 挂起教训**：初版尝试使用 `document.startViewTransition`，在无头自动化测试环境（Playwright Chrome 无 GPU/无沙箱模式）中，transition 捕获阶段会挂起页面渲染，导致 N10 套件大面积超时。通过二分回退定位后，果断改为纯 CSS keyframes 方案，彻底消除无头挂起隐患。
   - **断言选择器冲突修复**：N10 断言要求 `.inline-note > span` 仅包含 1 个文本块，而图标容器引入了多余 span；改用 `<b data-icon="alert">` 后 N10 56/56 全过。
5. **V5 审查收口与工作流验收适配（`c8a6973`）**：
   - **独立审查发现项当场修复**：标注空态 CTA 手动 `onclick` 与全局委托重复触发（造成 `loadLibrary` 双调用）已清理；溢出菜单点击重命名/删除后补充自动自闭合。
   - **默认端到端套件超时根因与适配**：在终跑 `python tools/check_workflows.py` 时，第 484 行 `await page.locator('#btnDelete').click();` 出现 30s 超时。经排查，由于 V2 将 `#btnDelete` 移入 `<details class="overflow-menu">` 中，未展开前元素不可见（not visible），Playwright 遵循真实操作可行性规则拒绝直接点击。适配在点击前补齐 `.overflow-menu summary` 展开动作，全链路一次性跑通。
