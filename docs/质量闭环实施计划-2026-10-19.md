# 质量闭环实施计划

2026-10-19。承接 [当前实现与验收状态](当前实现与验收状态.md) 的「已知欠账」与
[M01–M02 缺口分析](M01-M02缺口分析-2026-10-19.md) 的落地记录。
**本文只排计划，不改代码。**

## 〇、先修正一个前提

M01→M02 的正文获取**已经闭环**：候选池 + 「取全文（arXiv）」+「导入题录（需过核验）」
+ 本地手动上传。非 arXiv 论文由用户下载后走本地上传，**不再引入 Unpaywall / 出版商 API 认证**。
因此原缺口①（正文获取）不列入本计划。

剩下的缺口集中在三处：**测量、结构、验收**。

## 二、三批实施顺序

```
P1 测量地基    N05 漏提补录 → N06 质量面板
P2 结构安全    N12 原文块版本化 → N08 备份恢复
P3 验收与交付  N07 策略 A/B → 整篇长论文验收 → N11 安装验收 →（可选）N10
```

**为什么 P1 必须先做**：N06 的召回列、N07 的"谁更好"、整篇验收的"漏了多少"，
全都依赖"人能补一条机器没提的陈述"。没有 N05，后面每一项都只能给出半张表。

## 三、N05 漏提补录

### 目标
让人从原文补入机器未提出的陈述，并与机器结果**分开记录**。

### 改动点

| 层 | 改动 |
|---|---|
| schema v11 | 新表 `manual_claims(id, paper_id, analysis_hash, field, text, chunk_id, page, quote, note, created_at)`；不复用 `semantic_reviews`（那是裁决，这是采集） |
| 后端 | `POST /api/paper/{pid}/semantic/claims`（field/text/chunk_id/quote）；`GET .../semantic` 的 items 增加 `origin: machine\|manual` |
| 校验 | `quote` 必须能在 `chunk_id` 原文里逐字找到；`chunk_id` 必须属于该论文；`analysis_hash` 必须匹配当前分析 |
| 前端 | 右栏「补一条」：从原文选中句子 → 选字段 → 预览 → 保存；列表里人工条目用不同标记 |
| 指标 | `eval_extraction.py` 增加 `recall = manual / (machine + manual)`，未采集时仍显示 `n/a` |

### 验收标准
1. 补一条后，该论文的召回从 `n/a` 变成具体数字，且分母写明"机器 N + 人工 M"；
2. 人工条目**不**自动获得 `machine_supported` 状态，也不自动入库；
3. `quote` 与原文不匹配时拒绝保存，并指出第一个不匹配位置；
4. 换一版分析后，旧的人工条目仍可查看但标记"属于旧版本"。

### 风险
- **人为凑数**：补录必须绑原文引用，无引用的直接拒绝 —— 这条不能放宽。
- 补录条目参与召回分母，会让人有"少补 = 指标好看"的动机。口径上必须同时展示**人工补录绝对数**，不能只报比例。

### 落地记录（2026-10-19）

| 项 | 实现 |
|---|---|
| schema **v11** | `manual_claims(id, paper_id, analysis_hash, field, text, chunk_id, page, quote, note, created_at)` + 版本索引 |
| 校验 | 字段白名单、文本 ≤2000、引用必须**逐字**出现在该 chunk（折叠空白后比较，容忍 PDF 断行）、chunk 必须属于该论文、`analysis_hash` 必须匹配 |
| API | `POST /api/paper/{pid}/semantic/claims`、`DELETE .../claims/{cid}`；`GET .../semantic` 增加 `manual` 与 `recall` |
| 界面 | 右栏「人工补录」卡片：列表 + 删除 + 「补一条」表单（字段、原文块、选中文字作为引用、陈述内容） |
| 评测 | `eval_extraction.py` 的召回行从写死 n/a 改为按 `manual_claims` 计算 |

**口径修正（实测发现）**：首版 `ratio = manual / (machine + manual)`，在
`machine=0, manual=1` 时算出 **100%** —— 但机器根本没产出陈述，那不是"全漏了"，
而是没有分母。已改为**两边都有数才给比例**，否则 `None` 并说明缺哪一边。
界面显示 `n/a`，不会因为 `pct(null)` 而渲染成 0%。

测试：`tests/test_manual_claims.py` **20 项**（校验、去重、版本隔离、删除、召回口径、API）。
全量 **886 项通过**。

## 四、N06 质量面板

### 目标
把已有审核记录与 N05 补录聚合成一个可读的面板，**分字段**。

### 改动点

| 层 | 改动 |
|---|---|
| 后端 | `GET /api/paper/{pid}/quality`：按字段返回 `total / reviewed / verbatim / corrected / rejected / manual / recall` |
| 前端 | 论文详情页一个面板：字段 × 指标表格 + 覆盖率进度条 |
| 空状态 | 无审核记录时显示"尚无人工审核，指标不可用"，不显示 0% |

### 验收标准
1. 分字段展示，不合并成单一总分（总分掩盖"局限"字段 20% 这类问题）；
2. 同时显示**分母**：已审 / 总数；
3. 召回未采集时显示 `n/a`，不显示 0；
4. 面板数字与 `eval_extraction.py` 对同一份数据的结果一致（同源计算，不各写一套）。

### 落地记录（2026-10-19）

| 项 | 实现 |
|---|---|
| 共享聚合 | 新增 `src/litprism/quality.py`；`tools/eval_extraction.py` 改为调用它，**只剩一套口径** |
| API | `GET /api/paper/{pid}/quality` 返回 `fields[] / totals / has_data / note / definitions` |
| 界面 | 论文详情「质量面板」：字段 × 11 列，合计行加粗；无数据时隐藏表格并显示原因 |
| 联动 | 补录新增/删除后同时刷新质量面板（否则表里数字是旧的） |

**实测（临时库，6 条机器陈述 + 4 条审核 + 2 条补录）**：

| 字段 | 陈述 | 已审 | 逐字 | 修正 | 拒绝 | 补录 | 逐字精度 | 可用率 | 覆盖 | 召回 |
|---|---|---|---|---|---|---|---|---|---|---|
| 关键结论 | 3 | 3 | 1 | 1 | 1 | 1 | 33% | 67% | 100% | 25% |
| 方法论 | 2 | 1 | 1 | 0 | 0 | 0 | 100% | 100% | 50% | n/a |
| 局限与未来工作 | 1 | 0 | 0 | 0 | 0 | 1 | n/a | n/a | 0% | 50% |
| 合计 | 6 | 4 | 2 | 1 | 1 | 2 | 50% | 75% | 67% | 25% |

⭐ **口径细节**：`覆盖` 的分母是"陈述总数"，非零就给数字 ——
"6 条里 0 条审过"是确凿的 0%；而 `精度` 的分母是"已审数"，
没审过时不可知，必须是 `None`。两者不能混为一谈。

测试：`tests/test_quality.py` **19 项**。全量 **905 项通过**。

## 五、N12 原文块版本化

### 目标
同一篇论文再次导入时，新旧原文不混在一起。

### 改动点

| 层 | 改动 |
|---|---|
| schema | 新表 `materials(id, paper_id, source, content_hash, imported_at, level)`；`chunks` 增加 `material_id` |
| 导入 | `add_paper`/`add_chunks` 先建 material，再挂 chunks；`find_duplicate` 命中时返回已有 id 与材料版本 |
| 策略 | 导入时由调用方选择 `replace`（默认）或 `keep_both`；`replace` 旧 material 标 `superseded`，不物理删除 |
| 引用 | `analyses` 记录所用 `material_id`；旧分析的引用仍指向旧 material |
| 查询 | 默认只取 `current` material 的 chunks；`kb.get_chunks(paper_id, material_id=None)` 向后兼容 |

### 验收标准
1. 同一论文导入两次后，`get_chunks` 默认只返回最新版，块数不翻倍；
2. 旧分析的引用仍能解析到旧 material，不报"来源失效"；
3. `replace` 后 `papers.material_level` 只升不降的规则仍然成立。

### 风险
- 这是**破坏性 schema 变更**，必须先在临时库上跑迁移 + 全量测试，不能直接动主库。
- 旧分析不自动重写（沿用现有约定），但要能看出它基于哪一版材料。

## 六、N08 备份与恢复

### 目标
能整库导出、校验、恢复；失败可回滚。

### 改动点
- 导出：`litprism.db` + 可选原文 PDF + 清单（papers / 审核记录 / 产出 / 偏好计数）+ SHA256 校验
- 恢复：先预检（schema 版本、必需表、校验和）→ 写入新目录 → 校验 → 切换；失败保留原库
- 密钥**不随库迁移**：DPAPI 密文跨机器不可解，恢复后要求重新填 Key 并明确提示

### 验收标准
1. 导出→恢复→再导出，两次清单的校验和一致；
2. 恢复中断不会留下半套数据（要么完整切换，要么原库不动）；
3. 密钥缺失时明确提示"需要重新配置"，不静默用 mock。

## 七、N07 策略 A/B

### 前提
N05（补录）+ N06（面板）就位，且 N02 的固定样本与预算口径可复用。

### 方法
同一篇论文、同一模型、同一输出预算，分别跑 `whole` 与 `batched`，**只裁决差异**：

1. 按（字段, 归一化文本）对齐两份陈述；
2. 分出三类：只在 A / 只在 B / 都有但引用不同；
3. 人工只裁决这三类 + 补漏；
4. 记录分歧率、各自在分歧项上的正确率、补漏数、缓存命中率、实际用量。

### 验收标准
1. 报告必须同时给出**质量**（支持/修正/拒绝/漏提）与**成本**（token、调用数、缓存命中），不能只用条数或调用数宣称更优；
2. 样本独立性写明（同一篇重复跑不算两个样本）；
3. 回放与真实调用分开统计。

## 八、整篇长论文验收

现有 N02 结论是"控制集通过、整篇未通过"。补完 N05/N06 后应重跑，门槛事先定死：

| 指标 | 门槛（建议，需用户确认后锁定） |
|---|---|
| 未覆盖单元 | 0 |
| 待审比例 | < 20% |
| 人工补录数 | 记录绝对值，不设上限 |
| 逐字精度 | ≥ 70% |
| 整篇耗时 / 用量 | 记录，不设门槛但必须报告 |

**门槛必须在跑之前写进文档**，不能跑完再挑好看的指标。

## 九、N11 安装验收

安装包已产出，缺的是验收：

1. 干净机器（无 Python、无 Node）安装 → 启动 → 导入一篇 PDF → 解读 → 退出；
2. 覆盖升级：保留数据、不重复建库；
3. 卸载：程序移除，数据按设置保留；
4. 单实例：第二个实例不重复起 sidecar；
5. 启动失败路径：sidecar 缺失时给可读错误，不白屏。

---

## 十、口径纪律（贯穿全计划）

1. **未采集显示 `n/a`**，不用 0 或代理指标冒充；
2. 任何比例都要带分母；
3. 人工确认 ≠ 客观真实；
4. 机器支持 / 人工确认 / 原文覆盖是三种状态，不合并成"通过"；
5. 分字段报告，不合并成总分；
6. 成本与质量分开报，不用一个数字代替另一个。

---

## 十一、明确不做的

- 不引入 Unpaywall / 出版商 API（正文获取已由候选池 + 手动导入闭环）；
- 不做本地 embedding / 向量库；
- 不恢复 D3 扫描件转写；
- 不把 Zotero/BibTeX 同步纳入近期（现有导出不算同步）；
- 不为减少调用而降低复核强度。

---

## 十二、建议的下一步

**只做 N05**。它是唯一一项"做完之后，其他所有质量数字才开始有意义"的工作，
改动面小（一张表 + 两个接口 + 右栏一个按钮），且不依赖任何外部服务。

N05 完成后再决定 N06 与 N12 的先后 —— N06 让数字可见，N12 让数据可重导入，
两者互不阻塞，取决于你更想先看到质量还是先保证数据安全。
