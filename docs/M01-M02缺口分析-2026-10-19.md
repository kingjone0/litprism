# M01 / M02 缺口分析

2026-10-19。基于当前源码（`1930821`）核对 [M01](modules/01-来源发现与候选.md)、[M02](modules/02-论文与网页资料入库.md)
两份模块说明的"尚未接通"项，给出断点、影响、优先级与最小闭环路线。**本文只做分析，未改代码。**

## 一句话结论

两条链路各自都能跑通，**断点在两者之间**：M01 只能拿到题录/摘要，M02 也只保存题录/摘要块，
**没有任何环节负责"把材料真正取回来并标注完整度"**。
由此派生出最危险的一条：系统并不知道一篇论文是「全文」还是「只有摘要」，而下游（全文解读、
语义复核、导出）都按"已索引块"对待。

## 一、最危险的一条：材料完整度缺失（✅ 已于 2026-10-19 实现，见文末「落地记录」）

| 项 | 现状 |
|---|---|
| 题录导入 | `search.py:301` 写入 `{'page': None, 'section': '题录与摘要'}` |
| 表结构 | `papers` 有 `full_text`，**但没有** `material_level` / `has_fulltext` / `chunk_origin` |
| 解读侧 | 全库 grep 无任何"仅摘要"识别；`_coverage` 只报"已索引块 N/N 送达" |

**影响**：用户导入一条题录后点"解读"，界面会显示"22/22 块已送达、覆盖完整"，
但实际只有标题+摘要。这直接违背产品"不编"的定位——不是模型编，是**系统误导**。

**建议**（最小改动，优先级最高）：
1. `papers` 增加 `material_level`：`metadata` / `abstract` / `partial` / `fulltext`，导入时按入口写入；
2. 解读前若 `material_level in ('metadata','abstract')`，在结果和界面顶端明确提示，
   并拒绝把它标成"整篇"；`_coverage` 增加 `material_level` 字段；
3. 后续取得全文时升级该字段，而不是悄悄追加 chunks。

工作量：小（半天级），收益最大——它决定"已入库"这三个字是否可信。

## 二、M01 缺口（第 2 条候选池 ✅ 2026-10-19 已实现）

| 缺口 | 现状证据 | 影响 | 建议 |
|---|---|---|---|
| 无统一候选池 | `agents.py:489` 的 `candidates` 只在单次请求内存里；库里无候选表；查询条件/时间不留档 | 换个入口就要重新搜；无法比较、暂存、回溯"这条是怎么来的" | 新增 `source_candidates`（来源、原查询、URL/DOI、摘要、时间、状态：new/seen/imported/rejected） |
| 学术与网页是两条路 | 学术走 `search.py`，网页走 `evidence_routes.py:89` 的 Tavily | 同一研究问题下两类候选无法统一筛选 | 候选池用 `kind` 区分（paper/web/knowledge），复用已有 `evidence_sources.kind` 口径 |
| 去重只到题录级 | `find_duplicate()` 用 DOI 或 title+year 指纹；无 arXiv 版本、无 URL 指纹、无内容哈希 | 预印本/正式版被当两篇；网页重复入库 | 增加 `arxiv_id` 版本列、URL 规范化指纹、网页 `content_hash` 去重（已有 `content_hash`，缺去重查询） |
| 全文获取渠道未闭环（**arXiv 已实现**） | Unpaywall 仅配置字段、SearXNG 未实现（`discover_web()` 只有 Tavily）；arXiv 检索结果不自带 PDF 下载 | 检索到的东西进不了"可解读"状态 | 先做 arXiv 直链 PDF（合规、稳定），Unpaywall 次之 |

## 三、M02 缺口

| 缺口 | 现状证据 | 影响 | 建议 |
|---|---|---|---|
| 网页正文不抓取 | `include_raw_content=False`，只存标题/URL/摘要 | 网页侧永远只有摘要，"知识入库"体量受限 | 确认后按需抓正文并清洗，抓取失败保留摘要并标 `partial` |
| 论文 PDF 自动获取 | 无下载编排，只能用户手动导入文件 | 从候选到全文要人工搬一次 | 与 M01 的 arXiv 直链复用同一取回函数，落盘后走现有导入管线 |
| 重复导入不合并 | `add_chunks()` 是追加；`chunks` 无 source/version 列 | 同一论文二次导入会混入两版原文，页码/引用可能对不上 | chunks 增加 `material_id`（版本）并在导入时选择"替换/并存"；`find_duplicate` 返回已有 id 时不要静默追加 |
| 论文链接识别 | 无"URL → 论文"分类 | 粘贴论文网页链接只能当普通网页快照 | 用 DOI/arXiv 正则 + 站点白名单做一次轻量分类，命中则提示走论文入库 |

## 四、建议顺序（按"能形成闭环"排）

```
1. material_level（完整度）        ← 独立可做，立刻消除误导
2. 候选池 + kind 分类              ← M01 的地基，后续都挂在上面
3. arXiv 直链取 PDF → 现有导入管线  ← 打通"候选 → 全文"第一段
4. 网页正文抓取（按需）             ← 打通"网页 → 正文"
5. 版本合并（chunks.material_id）   ← 重复导入安全的前提
```

理由：1 不改任何流程就能防止误用；2 是 3/4 的落点；3 只要一个下载+落盘函数，复用现成解析；
4 依赖 2 的状态机；5 放最后，因为它需要前面把"材料"概念立起来。

## 五、不建议现在做的

- 增加更多搜索后端（SearXNG 等）：文档已指出"只增加 API 数量补不上正文获取缺口"。
- 自动批量抓取候选全文：没有候选池和完整度标记时，批量抓取只会批量制造"不明来源的材料"。

## 验收口径（每条都要能验）

- 完整度：仅题录的论文，解读结果第一行必须出现"本篇仅有题录/摘要"；
- 候选池：同一个查询重跑，能看到上次的候选与状态，不重复消耗检索额度；
- 取回：从候选点"取全文"后，`material_level` 升级，页面出现物理页定位；
- 版本：同一论文二次导入，旧 chunks 不会与新 chunks 混在一起。

## 落地记录（2026-10-19）

第 1 条已实现：

- schema **v9** 新增 `papers.material_level`（`unknown / metadata / abstract / partial / fulltext`），
  迁移按已有内容回填（有页码块=fulltext，仅题录摘要块=abstract，否则 metadata）。
- 三个导入入口写入：本地上传/CLI 导入 = `fulltext`；题录导入 = `abstract`（无摘要则 `metadata`）。
- 去重升级：同论文再次导入时**只升不降**，避免"题录覆盖全文"。
- 解读侧：`_coverage` 增加 `material_level / material_label / partial_material`，
  非全文时把提示顶到 `field_notes` 最前面；界面在覆盖信息上方显示"材料完整度"，
  部分材料用警示样式标注"覆盖 N/N 只代表已索引内容"。
- 测试 4 条：默认值与只升不降、迁移回填、题录导入写入、仅摘要论文的解读标注。

### 候选池落地记录（2026-10-19）

- schema **v10** 新增 `source_candidates`：`kind(paper/web/knowledge)`、`source`、`query`、`title/url/doi/arxiv_id/abstract/year/authors`、
  `fingerprint`（唯一）、`status(new/imported/rejected/ignored)`、`paper_id`、`created_at/updated_at`。
- 去重键按稳定性排序：**DOI > arXiv > 规范化 URL > 标题+年份**；URL 归一化去掉协议、`www.` 和尾部斜杠。
- 两条发现路径已接线：`POST /api/search`（学术）与 `POST /api/evidence/search`（Tavily 网页）都会留档，
  并返回 `candidates: {added, existing, total}`。
- API：`GET /api/candidates?kind=&status=&query=&limit=`、`POST /api/candidates/{id}/status`。
- 5 条测试：三形式收敛、按 kind/status/query 过滤、非法状态拒绝、导入后 paper_id 关联、URL 归一化。

尚未做：界面里的候选池列表（当前只有 API 与检索返回的计数）。

### arXiv 直链取全文落地记录（2026-10-19）

- `remote.py`：`arxiv_id_of()` 支持 arxiv_id 字段、`abs/`、`pdf/…v2.pdf`、`10.48550/arXiv.…` 四种形式；
  `download_pdf()` 只允许 arXiv 主机（含重定向后的主机复查）、80 MB 上限、`%PDF` 魔数校验。
- `fetch_candidate_pdf()`：下载 → `load_document` 解析 → 核验 → `add_paper(material_level='fulltext')` → 建原文块
  → 候选置 `imported` 并回链 `paper_id`。已存在同名 PDF 时复用，不重复下载。
- API：`POST /api/candidates/{id}/fetch`（无 arXiv 标识返回 400；网络/解析异常 502）。
- 真实网络冒烟（1607.01759）：**5 页 / 22 块 / verify=verified / material=fulltext**，与手动导入结果一致。
- 7 条测试：四种标识形式、主机白名单、重定向跨域拒绝、非 PDF 拒绝、成功入库并回链、失败不改状态、无标识不触网。
- 未做：非 arXiv 来源（Unpaywall/出版商页面）取全文。

### 候选池与知识库打通 + 界面（2026-10-19）

- **入库即识别**：`save_candidates` 写入时按 DOI → arXiv → 标题+年份 匹配 `papers`，命中则直接记 `imported` 并回链
  `paper_id`，不再以"新候选"堆积。
- **列表带状态**：`GET /api/candidates` 返回计算字段 `in_library` / `library_paper_id`，支持 `hide_in_library=1`。
- **手动补充**：`POST /api/candidates`（标题必有；有 arXiv/DOI 归为论文，否则归为网页），只留档不联网抓取。
- **对账**：`POST /api/candidates/sync` 把"先有候选、后导入论文"的存量补成 `imported`。
- **界面**（`发现文献` 视图）：候选池列表按查询分组，筛选「待处理/已在库/全部」，行内操作
  「取全文（仅 arXiv）」「导入题录（非 arXiv，需过核验）」「打开论文」「忽略」「拒绝」，右上「与知识库核对」「手动补充」。
- 非 arXiv 来源不做自动抓取（版权/登录）：只提供"导入题录"（必须过真实性核验），正文由用户手动下载后走本地上传。
- 桌面窗口改为无边框 + 系统控件叠层，顶栏即拖拽区，控件配色随主题同步（`preload.js` 单通道 IPC）。
