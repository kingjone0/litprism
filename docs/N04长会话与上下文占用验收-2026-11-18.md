## 会话范围与历史

- 会话在首条消息保存前可设置范围。之后点击顶部范围进入同一个新建对话入口，重新选论文、分组或全库。旧会话的消息和逐轮来源范围快照可继续查阅。API 尝试原地修改返回 409，改名和置顶走原接口。
- 范围限定本轮证据。有效历史回答和摘要用于理解指代和研究意图，结论须重新由本轮证据支持。选择分组时按当前成员取证，失效来源照常排除。已存在的会话使用现有范围。
- 压缩把较早原文换成摘要。系统提示、证据正文及送达清单位于历史和问题之前，相同前缀有机会复用。选中材料、来源顺序、材料版本或系统提示变化都可能提前打断公共前缀。服务端的缓存命中与计费需按实际返回的缓存用量验证。

## 聊天请求的前缀组织

模型收到的顺序是固定系统指令、完整送达的当前论文材料、有效历史、当轮变化的内容。显式选中的完整论文按会话范围顺序排在前面，其他完整论文按稳定论文 ID 排序。篇内沿原来的索引块顺序，编号在排序后统一绑定到原文。没有完整论文时直接从固定指令与历史开始。部分命中的原文、即时搜索摘要、人工知识、送达清单、偏好及当前问题留在后段。固定段只使用本轮实际选中且装得下的材料，检索范围和来源有效性照常校验。

历史按已有顺序附加新内容。压缩、人工裁决和来源失效仍可重建历史，稳定的系统指令和完整材料可先于这些变化复用。材料换版、选中集合变化或超窗裁剪会相应改变前缀。输出约束仍在当前问题附近。

DeepSeek 官方接口会匹配已保存的前缀，OpenAI 也推荐将稳定指令和材料前置。Anthropic Messages 支持用 `cache_control` 选择缓存边界。当前应用使用兼容的消息布局，缓存是否命中取决于实际服务及网关。Anthropic 用量归一将缓存读、缓存写和未缓存输入相加作为总输入。 [DeepSeek 上下文缓存](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/) · [OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching) · [Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

离线回归包含召回顺序反转、临时搜索结果、偏好更新、历史追加和材料替换，比较实际送给客户端的消息前缀和编号绑定。全量回归曾发现完全按 ID 排序会调换显式选择的两篇论文的编号，已改为优先使用选定顺序。

真实历史副本回放在 `_selftest.n04-prefix-foundation-20261118/replayed-real-history/`。Transformer 仍只送达所选论文与原检查点，本地估算总输入 14,502 token，其中系统指令和完整论文约 11,998 token，计入有效历史后的前缀约 12,678 token。换范围与撤回结果沿用固定样本核对。服务实际用量见下节。

最终 Python 全套 1,600 项、定向 38 项和完整无窗口工作流通过，Python 保留一条既有第三方弃用提示。
