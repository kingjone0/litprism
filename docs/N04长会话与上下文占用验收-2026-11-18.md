## 会话范围与历史

- 会话在首条消息保存前可设置范围。之后点击顶部范围进入同一个新建对话入口，重新选论文、分组或全库。旧会话的消息和逐轮来源范围快照可继续查阅。API 尝试原地修改返回 409，改名和置顶走原接口。
- 范围限定本轮证据。有效历史回答和摘要用于理解指代和研究意图，结论须重新由本轮证据支持。选择分组时按当前成员取证，失效来源照常排除。已存在的会话使用现有范围。
- 压缩把较早原文换成摘要。系统提示、证据正文及送达清单位于历史和问题之前，相同前缀有机会复用。选中材料、来源顺序、材料版本或系统提示变化都可能提前打断公共前缀。服务端的缓存命中与计费需按实际返回的缓存用量验证。

## 聊天请求的前缀组织

模型收到的顺序是固定系统指令、完整送达的当前论文材料、有效历史、当轮变化的内容。显式选中的完整论文按会话范围顺序排在前面，其他完整论文按稳定论文 ID 排序。篇内沿原来的索引块顺序，编号在排序后统一绑定到原文。没有完整论文时直接从固定指令与历史开始。部分命中的原文、即时搜索摘要、人工知识、送达清单、偏好及当前问题留在后段。固定段只使用本轮实际选中且装得下的材料，检索范围和来源有效性照常校验。

历史按已有顺序附加新内容。压缩、人工裁决和来源失效仍可重建历史，稳定的系统指令和完整材料可先于这些变化复用。材料换版、选中集合变化或超窗裁剪会相应改变前缀。输出约束仍在当前问题附近。

DeepSeek 官方接口会匹配已保存的前缀，OpenAI 也推荐将稳定指令和材料前置。Anthropic Messages 支持用 `cache_control` 选择缓存边界。当前应用使用兼容的消息布局，缓存是否命中取决于实际服务及网关。Anthropic 用量归一将缓存读、缓存写和未缓存输入相加作为总输入。 [DeepSeek 上下文缓存](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/) · [OpenAI Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching) · [Anthropic Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

离线回归包含召回顺序反转、临时搜索结果、偏好更新、历史追加和材料替换，比较实际送给客户端的消息前缀和编号绑定。全量回归曾发现完全按 ID 排序会调换显式选择的两篇论文的编号，已改为优先使用选定顺序。

真实历史副本回放在 `_selftest.n04-prefix-foundation-20261118/replayed-real-history/`。Transformer 仍只送达所选论文与原检查点，本地估算总输入 14,502 token，其中系统指令和完整论文约 11,998 token，计入有效历史后的前缀约 12,678 token。换范围与撤回结果沿用固定样本核对。服务实际用量见下节。

## 真实检查点后的固定追问

在提交 `bb0dbd9` 上，从 10 月 24 日验收库另建隔离副本，取截至 `m00013` 的会话，固定 Transformer 原论文 43 个块。题目未给出机制名：“刚才最后提到、用来抵消那种影响的机制叫什么？作者为什么说只用一个就会妨碍它发挥作用？请用两句话说明并标出论文出处。”

通过持久 Web 接口实际调用 DeepSeek V4.1 Flash 一次，搜索、扩展和重试各 0 次。实际请求带上摘要与 4 条有效的更早用户消息，旧 `m00009`–`m00012` 不以独立消息重复发送，摘要里的行内旧引用编号标为本轮无效。固定系统指令与全文前缀的哈希和上节一致。检查点来自旧版压缩，其中仍有少量结构化附件残片，本轮正文和引用未受影响。

首响正确把“那种影响”还原为对注意力加权位置求平均导致的有效分辨率降低，并识别多头注意力是论文给出的应对机制（第 2 页 [P8]）。第二句用第 5 页 [P18] 正确说明单头的平均会抑制对不同位置、不同表示子空间信息的联合关注。两个链接均由当前材料重新定位，页码和原文已逐条复核。该结果验证了带摘要的实际路径，摘要的独立贡献需要无摘要对照才可量化。

## 自动压缩边界离线验收

以当前提交 `bb0dbd9` 为基线，使用隔离库、1M 模型窗口、384K 输出预留和持久 Web 问答入口。小论文沿用冻结的 Transformer 原文 43 块，长论文与大量历史使用合成文字控制估算长度。实际经过请求组装、压缩事务和回读，记录器只接收 4 次本地问答，外部模型、搜索及知识确认均为 0 次。

| 控制 | 观察 |
|---|---|
| 阈值边界 | 可压增量 13,499 token 未触发，13,500 触发选段；历史压力 75%／95% 两档切换符合当前规则。比率先舍入到四位小数，实测 749,950 达到普通压力线，949,950 仍为普通档，949,951 进入紧急档 |
| 历史超阈 | 预置历史估算 800,752 token。普通问答完成后，自动落库检查点 `m00035`，把 `m00002`–`m00020` 的 475,462 token 折成 457 token。原记录可按块还原。候选从首答开始，首问仍在摘要外，确认问答配对缺口。持久结果的 `auto_compact` 为 null，数据库及后续请求均已看到检查点 |
| 压缩后追问 | 后一轮送入检查点与有效近期历史，未重复发送覆盖消息，系统提示和完整论文前缀哈希与前三次真实问答一致。本轮正确引用回到原块，伪造的 [P999] 被阻止；变更来源可信状态后，覆盖摘要退出模型上下文 |
| 论文挤占输入 | 合成全文 47 块完整送达，证据 591,109 token，最终估算输入 615,845 / 616,000。16 条可用历史只送出最后两条；历史压力约 17.65%，增长检查虽触发，300K 尾部保留预算没有腾出可压段，最终无检查点 |

本轮的两个主要反例分别来自选段和预算。选段需要把用户提问及其回答当成同一个单元，保护判断和压缩提交都应检查边界。发送预算应区分已存历史与实际剩余历史空间：组装本轮原文、指令和输出预留后，历史显著装不下时，应在发送前尝试压缩已完成的旧轮，优先保留最近完整问答、研究意图和有效摘要。问答后的检查可继续作为预防性路径。普通和极端场景优先用相同样本复验，再判断是否需要真实长窗口测试。

回放脚本及证据在 `_selftest.n04-auto-boundary-20261118/`，最终报告为 `baseline-b/report.json`。现有策略、持久问答、会话上下文和压缩生命周期的定向测试共 68 项通过。合成样本的收缩比只描述本地夹具，模型回答质量和长窗口实际计费沿用各自验收。

## 完整问答与发送预算修复复验

压缩选段以完整问答为单位。若保护区命中一条消息，整轮保留。提交时用当前消息重新检查问答边界，并拒绝重复覆盖。Web 问答在本轮论文、系统指令、问题和输出预留确定后测量历史剩余空间。当有效历史装不下，先尝试把旧的完整轮次抽成检查点，再装入最近完整问答和摘要。如果预算很紧，按实际可用空间缩短抽取式摘要。原对话和引用句柄继续可查。

|---|---|
| 约 801K 历史，首问与首答被拆开 | 首问首答一起保留。首次发送前检查点覆盖 `m00003`–`m00006` 两个完整轮次。后续请求保持同一系统与 43 个论文块前缀；有效引用回源，伪造引用被拦截，来源撤回后相关摘要退出模型上下文 |
