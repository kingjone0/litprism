> 并且回答之后可以把相关论文**收编入库**，让知识库在使用中生长。

## 一、问题的本质

用户的需求拆开是三件事：

1. **回答可以引用联网信息** —— 库里没有时不能一问三不知；
2. **回答后能把对应论文/知识加入知识库** —— 让库在使用中生长；
3. **不能破坏防幻觉体系** —— 这是整个产品存在的理由。

表面上看 1 和 3 冲突。实际上不冲突 ——
**防幻觉的保证从来不是"只用本地信息"，而是"每个结论可追溯、来源可信度对用户可见"。**

现在的体系只有一个信任层级（已核验本地文献），
所以看起来"外部信息 = 危险"。补法不是开个口子放网页内容进来，
而是**正式建立第二信任层级，并让两层在视觉与校验上彻底分离**。

---

## 二、两级证据模型

| | **Tier 1 · 文献证据** | **Tier 2 · 网络证据** |
|---|---|---|
| 来源 | 本地知识库（已核验论文的原文片段） | **实时抓取**的网页（搜索结果 + 页面正文） |
| 标记 | `[P1 p.3]` | `[W1]` |
| 校验 | 引用回溯：chunk 必须存在、页码必须一致 | URL 必须在**本次抓取集合**内 |
| 徽章 | ✅ 已核验 / 🔵人工确认 | ⚠️ 网页 · 未经核验 |
| 可否作结论依据 | 可以 | **只能作背景、线索、最新动态**；关键学术事实仍须文献支撑 |
| 与对方冲突时 | 优先 | 让位，并显式说明冲突 |
| 能否入库 | 已在库 | **可以**：经用户确认 + 核验后入库，升级为 Tier 1 |

**核心不变量（新增第 10 条）**：

> **网络证据只能来自实际抓取的页面。**
> 模型不得凭训练记忆"知道"某个网页说了什么 —— [W#] 引用的每一条，
> 都必须对应本次请求中真实抓取并放进上下文的内容。
> 这与文献证据的规则同构：不是"模型知道什么"，而是"上下文里有什么"。

这一条把网页幻觉的口子堵死了 —— 模型不能编 URL，不能凭印象转述没抓过的页面。

## 三、触发方式

| 方式 | 行为 |
|---|---|
| **显式开关** | 对话输入框旁一个「联网补充」开关（默认关）。开启后每次提问都带网络检索 |
| **自动建议** | 本地证据不足（`insufficient_evidence`）时，回答会附带"本地依据不足，可开启联网补充"的提示，一键开启 |
| **不做全自动** | 联网有成本与延迟，且默认关闭符合"最小惊讶" —— 用户明确要求才联网 |

## 四、执行链路（在现有框架上的落点）

```
提问
 ├─① search_local（现有）→ Tier 1 片段 [P#]
 ├─② 若开启联网：
 │     web_search（新增）→ 候选 URL
 │     抓取页面正文（复用 verify.py 的 _Http 缓存 + 新增正文提取）
 │     → Tier 2 证据 [W#]（URL / 标题 / 正文摘录 / 抓取时间）
 ├─③ 组装提示词：
 │     系统规范（现有，强制前置）
 │   + 【文献证据】块（现有）
 │   + 【网络证据】块（新增，标注"未经核验"）
 │   + 双通道引用规则（新增）
 ├─④ 模型回答
 ├─⑤ 双通道引用校验（扩展现有校验器）：
 │     [P#] → chunk 存在且页码一致（现有）
 │     [W#] → URL 在本次抓取集合内（新增）
 └─⑥ 渲染：文献引用照旧；网络引用用新组件，带"未经核验"徽章
```

**落点清单（复用 vs 新增）**：

| 环节 | 方式 |
|---|---|
| HTTP 抓取与缓存 | **复用** `verify.py` 的 `_Http` |
| 学术检索 | **复用** `search_external`（arXiv/OpenAlex 本就是联网 API） |
| 核验 | **复用** `PaperVerifier` |
| 导入 | **复用** `import_record` + Unpaywall |
| 网页搜索 | **新增** 可插拔 provider |
| 正文提取 | **新增**（requests + 简易正文抽取） |
| 双通道引用校验 | **扩展** 现有校验器 |
| `web-source-list` 组件 | **新增** lit-ui 组件 |
| 答后入库编排 | **新增**（检测 URL 中的论文特征 → 引导入库） |

## 五、网页搜索的 provider

可插拔，配置 `websearch: {provider, api_key_ref, max_results}`：

| provider | Key | 特点 |
|---|---|---|
| **tavily**（默认推荐） | 需要（有免费档） | 面向 LLM 设计，返回内容质量高 |
| **searxng** | 不需要（自托管） | 隐私好，用户自己部署 |
| duckduckgo | 不需要 | 零成本但抓取脆弱，仅作兜底 |

**不内置任何硬编码搜索** —— 没配 provider 时联网开关呈禁用态并说明原因。

## 六、回答后入库：让知识库在使用中生长

这是把"一次性问答"变成"越用越好"的关键。

### 流程

```
回答里出现 [W#] 网络引用
     ↓ 框架扫描 URL 中的论文特征（arxiv.org/abs/…、doi.org/…）
检测到 N 篇候选论文
     ↓ 显示「可入库」卡片：题录预览 + 一键核验
用户确认
     ↓ PaperVerifier 五态核验（已有）
     ├─ verified → Unpaywall 找 OA 全文 → 下载 PDF → ingest 入库
     ├─ likely   → 提示人工确认（走白名单流程）
     └─ not_found → 标记"无法入库"，保留为纯网页引用
     ↓
入库完成 → 提示「已入库 2 篇，下次同类问题可直接引用文献」
```

### 关键约束

- **必须用户确认**，不自动入库 —— 网络检索噪声大，自动入库会污染知识库
- **入库必走核验** —— 经 MCP 写入的约束同样适用：不接受无法确认真实性的文献
- 已在库中的论文自动跳过（按 DOI / arXiv ID / 指纹去重）
- 入库成功后，[W#] 引用处显示"已入库"标记，暗示下次可用文献证据回答

## 七、数据模型

```sql
-- schema v4：消息的网络引用
ALTER TABLE messages ADD COLUMN web_citations TEXT;
-- JSON: [{tag:"W1", url, title, snippet, source, fetched_at}]
```

- 与 `citations`（文献）**分字段存放** —— 两层证据在存储层就不混
- 消息渲染时分别产出 `citation-list` 与 `web-source-list`
- 导出时同样分节：「引用来源（文献）」与「网络来源（未经核验）」

## 八、提示词层的新规则（框架强制前置，Skill 无法移除）

在现有 `SYSTEM_ACADEMIC` 之后追加：

```
【网络证据使用规则】
1. 标记为 [W#] 的内容来自实时抓取的网页，未经学术数据库核验。
2. 引用网络内容必须使用 [W<编号>]，与文献引用 [P<编号>] 编号空间独立，不得混用。
3. 网络信息只能用于：背景说明、最新动态、非学术性事实。
   学术结论（方法效果、实验数据、领域共识）必须以文献证据 [P#] 为准。
4. 网络证据与文献证据冲突时，以文献为准，并明确指出冲突。
5. 不得引用上下文中未提供的网页；不得凭记忆补充"我记得某网站说过"。
6. 转述网页内容时保持原意，不得加工成超出页面表述的结论。
```

校验器新增：`[W#]` 指向的 URL 必须在本次抓取集合中；出现 `[W#]` 但没有网络证据块 → 校验失败。

## 九、实现排期

| 阶段 | 内容 | 依赖 |
|---|---|---|
| **W1** | web_search provider（tavily + searxng）+ 页面抓取与正文提取 + 提示词双通道 + **双通道引用校验** + `web-source-list` 组件 + chat 开关 | 需要一个搜索 Key（tavily 免费档）或自托管 searxng 实测 |
| **W2** | 答后入库编排：URL 论文特征检测 → 入库卡片 → 核验 → OA 下载 → ingest | W1 |
| **W3** | 本地证据不足时自动建议联网；`schema v4`（web_citations 字段） | W1 |

**与现有计划的衔接**：W1–W3 与 D3（扫描件转写）同类 —— 都改变证据进入系统的方式，
都需要真实 Key 实测，都建议**排在 Tauri 外壳之后、作为二期开头**。
原因：外壳打包会暴露一批只有真实桌面环境才有的问题，越早撞上越好；
而 W1 没有搜索 Key 之前只能用 mock 验证协议，实现完也是"待实测"状态。
