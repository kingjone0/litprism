**顶部标题区** —— 应用名 + 版本号（对齐参考图样式：名称粗体、版本号小字灰色）。
点击可打开「关于」。

**区块一 · 对话** —— 会话列表按最近更新排序；新建时可选绑定范围（全库 / 指定分组 / 指定论文）；
支持重命名、置顶、删除、按标题与消息内容搜索。

**区块二 · 知识库** —— 树形结构「分组 → 论文」。

| 能力 | 说明 |
|---|---|
| 分组管理 | 新建 / 重命名 / 删除 / 拖动排序 / 拖动论文跨组移动 |
| 论文条目 | 显示用户自定义名 + 核验状态点 |
| **重命名** | 见下方「重命名设计」 |
| **导出** | 见下方「导出设计」 |
| 删除 | 移入回收站（软删除，保留 30 天） |
| 批量操作 | `Ctrl` 多选 / 框选后批量导出、移动分组、删除、重新核验 |

**区块三 · Skill** —— 列出已加载的 Skill（名称 + 版本），点击在中栏打开 Skill 管理页。
**一期为空**，显示空状态："尚未添加 Skill"。区块底部固定一个「管理 Skill」入口。

**底部 · 设置** —— 固定在左下角，点击在中栏打开设置页。

**重命名设计（关键约束）**

必须区分两个字段：

- `papers.title` —— **原始题录标题**。用于核验比对、生成引用、导出 BibTeX。**重命名不改它。**
- `papers.display_title` —— 界面显示名。列表、侧边栏、标题栏优先显示。

若直接改 `title`，会同时破坏三件事：
① 核验比对失配，相似度骤降，**真实论文会被判成 `not_found`**；
② 导出的 BibTeX 带着随手起的名字，不符合学术规范；
③ 原始标题不可恢复。

界面上两者都可见，并提供「恢复原始标题」。

**导出设计**

| 范围 | 格式 | 说明 |
|---|---|---|
| 单篇 | Markdown 解读笔记 | 结构化字段 + 术语 + 引用来源 |
| | BibTeX / RIS | 标准题录，供 Zotero / EndNote 导入 |
| | JSON | 完整字段 + 核验证据，供二次开发 |
| 多篇 / 分组 | 合并 Markdown | 每篇一节，附目录 |
| | BibTeX 集合 | 单个 `.bib` 含全部条目 |
| | CSV 对比表 | 六维度矩阵，Excel 可开 |
| 全库 | 备份包（`.litprism`） | SQLite + 清单；**默认不含 PDF 本体**，可选包含 |

导出时附 `EXPORT-README.txt`，说明数据来源、核验状态与生成时间 ——
避免笔记脱离系统后丢失可信度信息。

### 1.4 中间工作区

视图：论文（解读 / 原文 / 术语 / 关联）、对话、对比、核验确认、推荐、交付物预览、
**Skill 管理页**、设置。
切换方式：左侧栏点击、标签页、命令面板（`Ctrl+P`）。

**对话视图采用生成式 UI 渲染**（详见 `回复展现层设计.md`）：
回复中的 `lit-ui` 围栏被渲染为白名单组件（论文卡片、解读面板、对比矩阵、核验结果等），
边生成边出现；渲染失败时逐级降级为纯 Markdown，绝不出现空白。

### 1.5 右侧检视面板

定位：**Inspector** —— 展示「关系」与「产出」，与中间工作区双向联动。

**Tab 一 · 图谱**

| 视图 | 数据来源 | 说明 |
|---|---|---|
| 知识图谱 | 本地 TF-IDF 余弦相似度 | 节点=论文，边=相似度；节点按核验状态或主题簇着色 |
| 引用网络 | OpenAlex `referenced_works` / `cited_by` | 可切换「它引用了谁」/「谁引用了它」 |
| 时间线 | 题录年份 + 引用关系 | 按年份排列的演进视图 |

交互：点节点 → 中栏打开该论文；悬停 → 题录摘要；框选 → 批量操作；
过滤：按分组 / 年份 / 核验状态 / 主题簇。

**Tab 二 · 交付物**（数据来自 `deliverables` 表）

| 类型 | 生成方式 | 说明 |
|---|---|---|
| 文献综述 | 任务模式「综述生成」 | 带引用的综述草稿 |
| 对比报告 | 内置对比 | 六维度矩阵 |
| 解读笔记 | 结构化解读 | 单篇或分组 |
| 审稿意见 | 任务模式「审稿人视角」 | 逐项评估 + 建议等级 |

每条显示：标题、类型、状态（草稿 / 已定稿 / 已导出）、引用处数、生成时间。
操作：预览（中栏打开）、导出、重命名、删除。

**Tab 三 · 上下文**

- 选中论文：题录（含原始标题）+ 核验证据与判定 + 术语表 + 关联论文 + 个人笔记
- 选中交付物：来源范围 + 生成用的任务模式与模型 + 引用清单 + 生成时间

**面板行为**：可折叠；宽度可拖拽（默认 260px，范围 200–420px）；三栏宽度均记忆到配置；
快捷键 `Ctrl+Alt+B`；窗口 < 1100px 自动折叠，< 900px 变为覆盖式抽屉。

**联动关系**

| 操作 | 联动 |
|---|---|
| 左栏选论文 | 右栏切到「上下文」并显示该论文 |
| 图谱点节点 | 中栏打开该论文，右栏上下文同步 |
| 交付物点条目 | 中栏打开文档预览 |

### 1.9 扫描件处理：改用多模态 API（v3 修订）

#### 1.8.1 实测依据

`tools/ocr_probe.py` 把有文本层的论文渲染成图片（模拟扫描件），
跑本地 `rapidocr-onnxruntime`，再与 PDF 原生文本层做基准比对：

| 样本 | 字符级相似度 | 基准行数 | OCR 行数 | 耗时 |
|---|---|---|---|---|
| 英文双栏 · 含公式（首页） | 0.9153 | 56 | 58 | 7.49s |
| 英文双栏 · 正文页 | 0.9184 | **27** | **55** | 6.18s |
| 中文单栏（封面） | 0.9714 | 3 | 4 | 2.38s |

**字符识别率看着不差，但版面语义完全崩坏。** 最致命的证据：正文页 OCR 输出的前 8 行是

```
Output / Probabilities / Softmax / Linear / Add & Norm / Feed / Forward
```

—— 这是 **Transformer 架构图里的图内标签**，被当成正文混进了文档流。
同时 27 行正文被切成 55 行（双栏跨栏行被拆碎），阅读顺序错乱。

**结论**：`rapidocr` 是"文本检测 + 识别"引擎，**不做版面分析、不做阅读顺序推断、
不区分图内文字与正文**。用它处理学术论文（双栏 + 公式 + 图表 + 表格），
得到的是一堆顺序错乱、混入图注的文本碎片 —— 对后续的核验、解读、引用定位都是污染。

#### 1.8.2 为什么多模态 API 更合适

多模态模型把页面**当成一张图整体理解**，天然处理三件本地 OCR 做不到的事：

1. **阅读顺序**：理解双栏排版，按正确顺序输出
2. **版面语义**：区分正文 / 图内文字 / 表头 / 脚注 / 页眉页脚
3. **结构还原**：直接输出 Markdown（标题层级、表格、公式 LaTeX），
   省掉自研版面分析的工作量

另外还有一个被低估的好处：**如果用户已经配置了多模态模型，这个能力是免费的附加项**，
不需要额外依赖、不需要额外配置、不增加安装包体积。

#### 1.8.3 成本测算

只对**没有文本层的页面**走这条路径，有文本层的直接解析（零成本、零误差）。

按 A4 页面 @200 DPI（1654×2339 px）渲染，主流多模态模型的图像 token 约 2000/页：

| 场景 | 页数 | 估算成本 |
|---|---|---|
| 一篇 15 页扫描论文 | 15 | ≈ $0.08 |
| 一篇 75 页扫描学位论文 | 75 | ≈ $0.40 |
| 个人一年 50 篇扫描件（均值 20 页） | 1000 | ≈ $5 |

> 关于"成本扛不住"的行业论调：那些论据针对的是**日处理十万页的工业单据场景**。
> 个人学术研究一年也就几百到几千页，且扫描件占比通常不到两成 ——
> 量级差了三到四个数量级，结论不能直接套用。

#### 1.8.4 导入流程

```
PDF 解析
  ├─ 逐页检查文本层
  │   ├─ 文本充足（> 阈值）──▶ 直接用文本层（免费、精确）
  │   └─ 文本不足（扫描页）──▶ 渲染成图 ──▶ 多模态 API 转写
  │                                          （要求输出 Markdown，区分图内文字）
  └─ 合并为统一文档结构 ──▶ 章节识别 ──▶ 分块 ──▶ 入库
```

界面提示：转写前显示预估页数与成本，由用户确认；转写结果标注「多模态转写」来源，
与文本层解析的页面区分开（便于后续核查）。

若用户未配置多模态提供商：提示"该 PDF 为扫描件，需要配置支持图像输入的模型才能导入"，
并给出设置入口，而不是静默失败。

### 1.10 本地能力边界（v3）

| 能力 | 运行位置 | 说明 |
|---|---|---|
| 解析、章节识别、分块 | 本地 | 纯计算，无模型 |
| 检索、相似度、图谱构建 | 本地 | 纯计算 |
| 题录补全、核验 | **联网** | 必须访问 Crossref / OpenAlex / arXiv |
| 结构化解读、问答、对比、推荐、任务模式 | **联网（API）** | 全部走 API 强模型 |
| 语义检索的嵌入计算 | **联网（API）** | 一次建索引约 $0.25 / 500 篇 |
| **扫描件转写** | **联网（多模态 API）** | v3 修订；实测证明本地 OCR 版面理解不可用 |

结论：**这是一个联网工具**。离线时只保留"读已导入的论文与已有解读"这类只读能力，
并在界面上明确提示"核验、解读与扫描件转写需要联网"。

## 二、Skill 框架（v4 定稿）

### 2.1 决定：建框架，不装内容

**完整实现 Skill 框架，但一期不内置任何 Skill**（包括不添加此前提议的
「文献综述生成」「审稿人视角评估」）。

完整规格见 **`Skill框架设计.md`**，此处只列要点。

这个顺序是刻意选的：

1. **框架是架构决策，内容不是。** 扩展点形状定错了，后面每加一个 Skill 都要绕；
   定对了，加内容只是写两个文件。
2. **空容器能真实验证扩展点够不够用。** 只在自写 Skill 上验证过，容易把
   "恰好够用"当成"足够通用"。
3. **验证不依赖内置 Skill。** 用测试夹具（临时目录构造的 Skill）覆盖框架行为，
   而不是靠"顺手写一个 Skill 来测"—— 后者会让测试和业务耦合。

### 2.2 框架要点

| 项 | 内容 |
|---|---|
| 位置 | `<数据目录>/skills/<skill-id>/`，含 `skill.yaml` + `prompt.md` |
| 形态 | **仅声明式**：提示词 + 输入契约 + 上下文声明 + 能力白名单 + 输出形态 |
| 能力 | 只能调用**固定能力表**（search_passages / search_papers / get_analysis / list_collections / get_graph / verify_paper / compare_papers），不可自带实现 |
| 上下文 | 一期用**声明式预取**（清单里写清要检索什么，框架调用前一次性取好注入），不用工具调用循环 |
| 输出 | `deliverable`（落 `deliverables` 表）/ `answer` / `analysis` |
| 校验 | 能拒绝的早拒绝（版本/id/能力/变量），不确定的只警告；**不静默降级** |

### 2.3 安全边界（硬性）

- **一期只支持声明式 Skill，不支持自定义代码。**
  允许携带可执行代码 = 开放任意代码执行入口，用户从别处拿来的 Skill
  就能在你机器上跑任意逻辑。要支持必须先有沙箱方案，那是独立工程。
- **防幻觉约束不可绕过**：全局学术规范与防幻觉约束由框架**强制前置**，
  Skill 作者无法移除或覆盖；`citation_required: true` 时引用回溯校验由**框架**执行。
  用户自行添加的 Skill 是系统里最不可信的输入源，若能绕过约束，前面三层防线就白建了。
- Skill 目录只读加载，不执行任何脚本；加载失败不影响应用启动。

### 2.4 与内核能力的关系

**必须区分两件事：**

| | 内核能力 | Skill |
|---|---|---|
| 内容 | 结构化解读、术语解释、问答、对比、查询扩展 | 用户自行添加的扩展 |
| 位置 | 硬编码在 `prompts.py` | `<数据目录>/skills/` |
| 可扩展 | 否，仅可查看与微调提示词 | 是，走框架加载 |
| 一期状态 | 全部实现 | **空** |

命令面板（`Ctrl+P`）会同时列出内核能力与已加载 Skill；
一期只有内核能力，Skill 区域显示空状态引导。

## 三、MCP 规划（v3 定稿）

### 3.1 核心判断：内核是库，MCP 是适配层

```
        LitPrism 内核（纯 Python 库 · 唯一事实来源）
        ├── CLI 适配层           → 开发者 / 自动化脚本
        ├── HTTP API 适配层      → 桌面应用前端（sidecar）
        └── MCP Server 适配层 ★  → Claude Desktop / Cursor / 其他 Agent
```

**内部调用绝不走 MCP。** CLI、桌面端、内置任务模式全部直接调进程内函数。
内部走 MCP 等于自己给自己发 stdio/HTTP 请求，纯增加序列化开销与失败点，没有收益。

### 3.2 一期：只做对外的 MCP Server

**为什么值得做**：

1. 知识库变成**可被任意 Agent 使用的基础设施**，而不是孤立的桌面应用
2. 最高价值的 tool 是 `verify_paper` —— **任何 Agent 都能用它防止编造文献**，
   这是当前 AI 辅助科研最普遍的痛点
3. 复用已有的检索、核验、解读能力，不必在别处重建
4. 工作量小：它是薄适配层，不改变内核

**暴露的 Tools**

| Tool | 输入 | 说明 |
|---|---|---|
| `litprism_search_papers` | query, limit, collection_id | 检索本地库题录 |
| `litprism_search_passages` | query, top_k, paper_ids | 检索原文片段，返回页码可作引用定位 |
| `litprism_get_analysis` | paper_id | 取结构化解读 |
| **`litprism_verify_paper`** | title 或 doi | ⭐ **核验真实性，返回四态判定 + 候选匹配 + 证据** |
| `litprism_compare_papers` | paper_ids, aspects | 多篇对比矩阵 |
| `litprism_list_collections` | — | 分组树 |
| `litprism_get_graph` | threshold | 知识图谱数据（节点 + 边） |
| `litprism_import_paper` | doi 或 title | 核验通过后入库（默认关闭） |

Resources：`litprism://papers/{id}`、`litprism://collections/{id}`。传输：stdio 为主。

### 3.3 一期不接入任何外部 MCP 服务

逐项分析过候选服务后，结论是**大部分候选的价值可以用原生实现替代，而且更简单**：

| 候选 MCP | 原生实现能否替代 | 结论 |
|---|---|---|
| 文件系统扫描 | ✅ 就是遍历目录 + 后缀过滤 | 原生做，不引 MCP |
| Obsidian / Notion 输出 | ✅ 就是写 Markdown 文件 | 原生做，不引 MCP |
| Zotero | ⚠️ 部分。二期做 BibTeX 导入导出可覆盖约 80% 需求 | 先做 BibTeX，不够再评估 |
| arXiv / Crossref / OpenAlex | ✅ 已有内置实现 | 不引 MCP |
| SQLite | ✅ 内部直接访问更快更安全 | 不引 MCP |
| **GitHub** | ❌ 需要认证的第三方 API，原生做要自己处理鉴权与限流 | **二期候选**，服务「复现性检查」 |
| 通用搜索引擎 | — | 不引，与防幻觉目标冲突 |

**判断原则**：MCP 真正的不可替代价值在于**连接需要认证的第三方云服务**。
凡是能用几行本地代码做完的事，引入一个独立进程去承担，是纯粹的复杂度负债。

### 3.4 二期：按实际需求接入

- **GitHub MCP** —— 查找论文的官方实现仓库，服务复现性检查。优先度最高。
- **Zotero** —— 若 BibTeX 导入导出在实战中不够用，再考虑。
- 其他 —— 用到再说，不做"MCP 市场"式的开放接入。

### 3.5 安全边界（硬性）

- 对外的 MCP Server 默认**只读**；`import_paper` 这类写操作需显式开启
- 所有调用记入 `mcp_audit`（时间、工具、参数摘要、结果状态）
- ⭐ **经 MCP 写入的数据同样必须走核验流程** ——
  否则外部数据可绕过防幻觉第 3 层防线，整套体系形同虚设
- 若二期引入外部 MCP 服务：默认不启用，需用户显式确认；写操作二次确认

## 四、数据模型增量

```sql
-- 知识库分组
CREATE TABLE collections (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, parent_id TEXT,
  sort_order INTEGER DEFAULT 0, created_at TEXT
);

-- 对话与消息（左侧栏"对话"区块）
CREATE TABLE conversations (
  id TEXT PRIMARY KEY, title TEXT NOT NULL,
  scope TEXT,                      -- JSON：绑定的分组/论文 id，NULL = 全库
  model TEXT, pinned INTEGER DEFAULT 0,
  created_at TEXT, updated_at TEXT
);
CREATE TABLE messages (
  id TEXT PRIMARY KEY, conversation_id TEXT NOT NULL,
  role TEXT NOT NULL, content TEXT,
  citations TEXT,                  -- JSON：引用片段
  citation_check TEXT,             -- JSON：引用回溯校验结果
  meta TEXT, created_at TEXT,
  FOREIGN KEY (conversation_id) REFERENCES conversations(id) ON DELETE CASCADE
);

-- 交付物（右侧栏"交付物"tab）
CREATE TABLE deliverables (
  id TEXT PRIMARY KEY,
  type TEXT NOT NULL,              -- review | comparison | notes | peer_review
  title TEXT NOT NULL,
  mode_id TEXT,                    -- 生成它的任务模式
  source_scope TEXT,               -- JSON：来源论文/分组
  content TEXT,                    -- Markdown 正文
  citations TEXT,                  -- JSON：引用清单
  status TEXT,                     -- draft | final | exported
  model TEXT, created_at TEXT, updated_at TEXT
);

-- 模型提供商
CREATE TABLE providers (
  id TEXT PRIMARY KEY, name TEXT NOT NULL,
  base_url TEXT NOT NULL,
  api_key_ref TEXT,                -- 加密存储的引用键，不存明文
  chat_model TEXT,
  embed_model TEXT,                -- 嵌入模型（二期用）
  multimodal INTEGER DEFAULT 0,    -- 是否支持图像输入（决定能否承担扫描件转写）
  is_custom INTEGER DEFAULT 0,
  status TEXT, status_note TEXT, checked_at TEXT,
  sort_order INTEGER DEFAULT 0
);

-- MCP 服务与审计
CREATE TABLE mcp_servers (
  id TEXT PRIMARY KEY, name TEXT NOT NULL,
  transport TEXT, command TEXT, args TEXT, env TEXT,
  readonly INTEGER DEFAULT 1, enabled INTEGER DEFAULT 0, created_at TEXT
);
CREATE TABLE mcp_audit (
  id TEXT PRIMARY KEY, server_id TEXT, tool TEXT,
  args_digest TEXT, ok INTEGER, error TEXT, created_at TEXT
);

-- papers 表新增
ALTER TABLE papers ADD COLUMN collection_id TEXT;
ALTER TABLE papers ADD COLUMN display_title TEXT;   -- 用户重命名后的显示名
ALTER TABLE papers ADD COLUMN sort_order    INTEGER DEFAULT 0;
ALTER TABLE papers ADD COLUMN deleted_at    TEXT;   -- 回收站（软删除）

-- 扫描件转写记录（便于区分来源、核算成本、失败重试）
CREATE TABLE ocr_jobs (
  id TEXT PRIMARY KEY, paper_id TEXT, page INTEGER,
  provider_id TEXT, model TEXT,
  status TEXT,                     -- pending | ok | failed
  tokens INTEGER, cost_usd REAL, error TEXT,
  created_at TEXT
);
```

**API Key 存储**：不明文落盘。Windows 用 DPAPI（`CryptProtectData`）或凭据管理器；
跨平台可用 `keyring`。数据库只存引用键。界面上「打开配置文件」指向的 `config.yaml`
只放非敏感项。
