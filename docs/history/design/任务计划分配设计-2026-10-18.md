## 一、两个约束其实可以合并成一个

先量化（当前代码实测）：

| 量 | 实测值 |
|---|---|
| 带引文的单条陈述 | **64 token** |
| 输出预算 4096 的保守配额（留 30% 余量） | **44 条/任务** |
| 陈述密度（fastText 19 条/4k、GPT-3 240 条/60k） | **4–5 条 / 1k 输入 token** |

于是可以反推：

```
输入上限 = 输出配额 ÷ 陈述密度 = 44 ÷ 4.5 ≈ 10k token
```

**输入 ≤ 10k token，输出 ≤ 44 条，二者自洽。**

这个数字同时解决两个约束：

- **输出容量**：10k × 4.5 = 45 条 × 64 token ≈ 2.9k 输出，4096 预算下留 30% 余量 ✅
- **注意力质量**：10k 输入远低于"lost in the middle"显著退化的区间（通常 30k+ 才明显）✅

**所以不需要为两个约束分别设计 —— 一个输入上限就同时管住了。**

## 二、但章节体量极不均匀，必须再切

实测章节体量：

| 论文 | 全文 | 最大章节 |
|---|---|---|
| GPT-3（62 页） | 60,553 | **结果 20,963（35%）** |
| Attention（10 页） | 8,459 | 方法 4,540（54%） |
| BERT（12 页） | 12,362 | 方法 2,572（21%） |

GPT-3 的「结果」一节单独就 21k token → 约 95 条陈述 → **超过 44 配额两倍**。
所以"按章节切"还不够，**超长章节要再切块**。

## 三、分配算法

```
① 章节切分（机械，按标题识别）
     识别失败 → 退回固定块切分，并在 coverage 里标注「章节结构不可用」

② 超长章节再切
     章节 token > 10k → 按 chunk 边界均分成 ⌈tokens/10k⌉ 块
     （不切在句子/表格中间 —— 复用现有的表格行保护逻辑）

③ 字段 × 章节块 映射（表驱动，不调模型）
     方法      → methodology, experiment_design
     实验/结果 → experiment_design, key_conclusions
     引言      → research_question, innovations
     结论      → key_conclusions, innovations, limitations
     局限      → limitations

④ 组装任务
     输入 = 目标块 + 摘要 + 结论（后两者作全局锚点，通常各 < 1k）
     输入 ≤ 10k token（超出则回到 ② 再切）
     输出配额 = 44 条
     期望条数 = [输入token × 3.5, 输入token × 6]   ← ±40% 容差
     理由字段：写明"为什么这个任务读这一段"（可审计）

⑤ 输出计划（JSON），可存档、可重放、可人工审阅
```

**为什么带摘要和结论**：目标章节之外的指代（"如 3.2 节所述""我们的主要发现"）
需要全局锚点。摘要和结论都很短，加进来只增加约 1k token，却能显著减少跨章节误读。

## 四、注意力质量无法保证，只能**检测**

这是必须说清楚的一点：没有任何分配方式能"保证"模型读全了中段。
能做的是**用机械闸门把漏读抓出来**。

### 章节覆盖闸门

每个任务执行后，比对实际条数与期望区间：

| 情况 | 判定 | 动作 |
|---|---|---|
| 实际 < 期望下限 | **疑似漏读** | 重跑该块，提示"这段约 N 字，你可能漏了内容" |
| 期望区间内 | 正常 | 通过 |
| 实际 > 期望上限 | 疑似重复/编造 | 标记待人工核对，不自动通过 |
| 输出被截断 | 配额不足 | 该块再切半，重跑 |

**这个闸门是注意力质量的唯一可观测代理。** 它不完美（模型可能"编满"而不报错），
但配合引用逐字匹配闸门，能挡住大部分情况。

### 其余闸门（全部机械、零成本）

- JSON 完整未截断
- 每条陈述至少 1 个引用标签
- 引用的 quote 能在对应 chunk 里逐字找到
- 含数字的陈述能抽出（值，单位）
- 同一 chunk 被引用次数不超过阈值（防"一句多用"）

## 五、计划的数据结构

```json
{
  "paper_id": "p_x",
  "version": 1,
  "structure": {
    "sections": [{"id": "s3", "title": "方法", "tokens": 13512, "blocks": 2}],
    "fallback": false
  },
  "tasks": [
    {
      "id": "t1", "field": "methodology", "section_ids": ["s3"],
      "block": 1, "input_tokens": 6800,
      "expected_claims": [24, 41],
      "quota": 44,
      "reason": "方法节前半：模型结构描述"
    }
  ],
  "gates": ["json_complete", "has_citation", "quote_verbatim",
            "numeric_parse", "section_coverage"],
  "repair": {"max_rounds": 2}
}
```

**计划本身可评测**：同一篇论文用不同策略（全文 vs 分块）生成的计划可以对比 ——
任务数、覆盖期望、预估成本，都是可比的数字。

## 六、修复循环（有界）

```
for round in 1..2:
    for task in 未通过闸门的任务:
        重跑（带上失败原因："上一轮这段只提出 3 条，疑似漏读"）
    重新过闸门
剩余未通过的 → 标记「未覆盖」，写入 coverage，不伪装成通过
```

最多 2 轮，硬上限。第三轮收益递减而成本线性。

## 七、这样能达到你想要的效果吗？

逐条对照：

| 你的目标 | 能否达到 | 说明 |
|---|---|---|
| **输出容量有保障** | ✅ 可以 | 输入 ≤10k → 输出 ≈45 条 < 44 配额，留 30% 余量；超长章节再切 |
| **注意力质量有保障** | ⚠️ **不能保证，但能检测** | 覆盖闸门抓漏读并重跑；但模型"编满"时报不出来，仍需人工 |
| **效果可评判** | ✅ 可以 | 每个任务有期望区间，通过率 = 可测的质量指标 |
| **人工参与丰富知识库** | ✅ 可以 | 计划可审（人先看要读哪些段），低覆盖块成为重点复核对象 |
| **成本可控** | ✅ 可以 | 任务数确定，修复有上限，估算可提前算 |

### 估算：GPT-3（60k token）

| 阶段 | 任务数 | 说明 |
|---|---|---|
| 提取 | 8–10 | 6 字段 × 相关章节块 |
| 闸门 | 0 调用 | 机械 |
| 修复 | 0–4 | 只重跑未通过的 |
| 复核 | 30 | 8 条/次，240 条全覆盖 |
| 差异 | ~10 | 机械数值 + 选择性语义 |
| **合计** | **~50 次** | 对比现状 88 次 / 覆盖 20% |

## 八、一个诚实的边界

**"注意力质量"这件事，分配算法只能降低风险，不能消除。**

真正的验证只有一条路：**人工在长文的中段抽样核对**，看机器提的陈述是否覆盖了那部分的关键内容。
这就是 [效果评判](效果评判与阅读即标注-2026-10-18.md) 里说的"阅读即标注" ——
不是可选项，是这个体系能不能自证的关键。

所以在实现顺序上，我建议：

1. **先做分配算法 + 闸门**（本方案）—— 把覆盖从 20% 拉到接近 100%，且可测
2. **再做「补一条」**（E-1）—— 让"漏提"可测量
3. **最后做 A/B**（全文 vs 分块）—— 用真实数据验证"10k 分块"是不是真的比"全文单次"好

第 3 步之前，"10k 上限"是基于密度与注意力研究的**推算**，不是实测结论。
