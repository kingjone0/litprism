## 已确认的问题

优先级：P1 表示影响核心可信度或使已宣称的主要能力不可用；P2 表示功能闭环、可靠性或信息表达缺口。

### R01 · P1 · 本地核验失败后仍可入库，并进入可通过检查的问答引用

上传 API 虽然执行核验，却无条件调用 `kb.add_paper`。CLI `add --verify` 也只保存核验结果，没有阻止后续入库。问答检索及数据库检索没有统一过滤 `is_citable`。

离线复现：`/api/upload?verify=true&analyze=false` 的核验桩返回 `not_found`，接口仍 `200 / ok=true`，论文与片段已保存。随后真实检索召回该片段，模型桩引用其真实页码，`citation_check_passed=true`。因此“编号与页码正确”没有保证文献通过核验。

定位：[server.py:216](E:/codex-litprism/src/litprism/web/server.py:216)、[cli.py:172](E:/codex-litprism/src/litprism/cli.py:172)、[agents.py:90](E:/codex-litprism/src/litprism/agents.py:90)、[db.py:325](E:/codex-litprism/src/litprism/db.py:325)。

建议：统一所有导入入口；如果需要保存未核验本地文件，必须明确作为待核验资料隔离，不能进入可引用证据集合。两种产品策略需统一定案并由公共代码执行。

### R02 · P1 · 无证据 Skill 可生成、通过校验、落交付物并导出

`SkillRunner` 在无片段时仍调用模型。`_check_citations` 在“没有片段且回答也没写引用”时返回通过，即使 `citation_required=true`。后续照常保存交付物。交付物渲染只在 citations 非空时附引用段，导出没有前置守卫，也没有保存本轮引用检查结果。

离线复现：合法的 `citation_required` Skill，`excerpts=0`，模型桩输出无依据学术结论，结果为 `ok=true / citation_passed=true / deliverable_saved=true`。继续导出成功，文件不存在 `## 引用来源`。

定位：[runner.py:153](E:/codex-litprism/src/litprism/skills/runner.py:153)、[runner.py:367](E:/codex-litprism/src/litprism/skills/runner.py:367)、[deliverables.py:274](E:/codex-litprism/src/litprism/deliverables.py:274)。

建议：对需要学术证据的 Skill 执行前拒答；统一保存校验结果并区分“失败草稿”和“可交付产物”；导出守卫不能由模板是否列出引用决定。

### R03 · P1 · 解读和对比没有达到问答同等的引用回溯约束

解读上下文将各页文本按章节拼接，丢失 chunk/page 标识，输出直接存储。对比主要使用解读字段/摘要，模型返回的 evidence_map 未做来源校验。

离线复现：对比模型桩输出不存在的 `[P999 p.999]`，`CompareAgent.compare` 原样返回，结果没有引用检查字段。这不证明真实模型一定编造，但证明框架不能拒绝这一明确反例。

定位：[extract.py:30](E:/codex-litprism/src/litprism/extract.py:30)、[extract.py:80](E:/codex-litprism/src/litprism/extract.py:80)、[agents.py:270](E:/codex-litprism/src/litprism/agents.py:270)。

建议：解读字段保留原文句柄；对比结论引用原文证据，并复用框架校验，避免仅从生成过的解读再生成结论。

### R04 · P1 · Web 人工放行后，再核验仍不认白名单

Web 创建共享核验器时只传了 `cfg`；CLI、MCP 与 Skill 的核验路径则传入 `Whitelist(kb)`。

离线复现：通过 `/api/whitelist` 保存人工确认后，`/api/verify` 返回 `unchecked`；同一临时库直接调用带白名单的核验器返回 `manual_confirmed`。所有在线数据源均关闭，因此没有网络不确定性。

定位：[server.py:74](E:/codex-litprism/src/litprism/web/server.py:74)。

建议：所有核验入口使用统一工厂并挂载同一白名单，确认依据与自动判定也应由后端保存，不能只依赖客户端提交的等级。

### R05 · P1 · MCP ask 在配置模型后必然返回方法不存在错误

MCP 调用 `QAAgent.answer()`，实际接口是 `ask()`；紧接着还读取不存在的 `ans.citations` / `ans.check` 字段。

离线复现返回：`ok=false`，`AttributeError: 'QAAgent' object has no attribute 'answer'`。现有 MCP ask 测试只覆盖“没有模型”的前置拒绝，因此未经过这条路径。SDK 构造成功不等于工具调用成功。

定位：[tools.py:250](E:/codex-litprism/src/litprism/mcp/tools.py:250)、[test_mcp.py:154](E:/codex-litprism/tests/test_mcp.py:154)。

建议：同步 QAAnswer 字段，补有模型且有证据的 MCP 工具端到端用例，再通过真实 stdio 客户端验证。

### R06 · P1 · 文献范围未被一致执行

聊天创建会话时保存 scope，实际调用 QAAgent 时没有传入 paper_ids；降级 LIKE 检索拼接多个 OR 条件时未加括号，追加的 `AND paper_id IN (...)` 不能约束所有 OR 分支。

离线复现：scope 只绑定 A，聊天问题只命中 B，来源返回 B。另用无效 FTS 表达式触发降级，明确传入 `paper_ids=[A]`，结果仍包含 B。

定位：[server.py:348](E:/codex-litprism/src/litprism/web/server.py:348)、[server.py:423](E:/codex-litprism/src/litprism/web/server.py:423)、[db.py:355](E:/codex-litprism/src/litprism/db.py:355)。

建议：将范围解析为统一的后端过滤条件，在正常检索、降级检索、问答、Skill、MCP 各入口落实。MCP search_passages 还应先限定 paper_id 再做 top_k，避免全库截断后才过滤而漏检。

### R07 · P1 · 原文无页码时，模型虚构页码仍能通过

问答检查仅在“模型页码和实际页码都为真值”时比较。实际 page=None 的情况下，不会拒绝模型写出的任意页码。

离线复现：真实片段 `page=null`，回答 `[P1 p.1]`，检查返回 true。Skill 也有类似“actual is not None 才检查”的边界。

定位：[agents.py:209](E:/codex-litprism/src/litprism/agents.py:209)、[runner.py:388](E:/codex-litprism/src/litprism/skills/runner.py:388)。

建议：没有页码的来源只能使用无页码引用并显示无页码；模型提供的无法证明的页码应判失败，不能略过。

### R08 · P1 · mock 解读在论文详情页没有显式声明

MockLLM 输出 `_mock=true`，Markdown 导出有占位声明；论文详情页却直接渲染六个字段，没有使用 `_mock` 或接口返回的 markdown 声明。

headless 复现：模拟接口返回 `_mock=true`、解读字段及明确的 mock 声明；详情页成功展示字段，`disclaimerShown=false`。问答的 mock 文本本身带提示，本问题特指论文解读展示。

定位：[app.js:407](E:/codex-litprism/src/litprism/web/static/app.js:407)、[extract.py:184](E:/codex-litprism/src/litprism/extract.py:184)。

建议：在解读、术语、对比、交付物等各产物显式展示生成模式、模型与生成时间；mock 结果不能在界面重开后失去身份标记。

### R09 · P2 · 选中模型与实际执行模型不一致；“重新解读”没有强制重算

只有聊天从 ProviderStore 构建当前选中模型。单轮 ask、解读、对比和推荐仍使用 create_app 时构建的 llm。界面“重新解读”也没有传 `force=true`，已缓存时直接返回旧结果。

离线复现：选中模型收到 chat 的 qa；解读 `_model` 仍是 `startup-default`。已有解读 `Known RQ` 时，默认重解读 API 返回相同缓存，新增模型调用数为 0。

定位：[server.py:72](E:/codex-litprism/src/litprism/web/server.py:72)、[server.py:181](E:/codex-litprism/src/litprism/web/server.py:181)、[app.js:470](E:/codex-litprism/src/litprism/web/static/app.js:470)、[extract.py:67](E:/codex-litprism/src/litprism/extract.py:67)。

建议：明确全局模型与任务专用模型的契约，统一解析；重解读应发起强制重算，保留旧产物及新旧模型信息。

### R10 · P2 · 请求预算只裁减历史，不能保证完整请求不溢出

新接线在扣除当前消息、证据与系统指令后，用剩余预算挑选历史；当基础请求自身已超预算时，只会令 remaining=0，仍向模型发送超额请求。压缩在回答后基于数据库消息测量，不涵盖完整请求。Policy 有溢出重试判定方法，实际调用没有接入恢复重试；Telemetry 也未接提供方真实 usage。

边界复现：可用预算 150 token，实际送入桩模型的请求按同一 Meter 估算为 728 token，仍执行了 qa。此用例故意缩小窗口以复现边界，不代表普通 32K 窗口每轮都会溢出。

定位：[agents.py:154](E:/codex-litprism/src/litprism/agents.py:154)、[server.py:480](E:/codex-litprism/src/litprism/web/server.py:480)、[telemetry.py:179](E:/codex-litprism/src/litprism/context/telemetry.py:179)。

建议：对完整请求 envelope 做请求前预算，优先保证证据与全局约束，超额时有明确裁剪/拒绝/一次恢复策略；返回实际裁减与计量依据。

### R11 · P2 · 最低相关度设置未被检索执行

设置页允许填写 retrieval.min_score，检索过程没有使用它。

离线复现：阈值 1.0 时，仍返回 score 为 0.6908、0.5436 的片段。

定位：[app.js:1175](E:/codex-litprism/src/litprism/web/static/app.js:1175)、[search.py:18](E:/codex-litprism/src/litprism/search.py:18)。

建议：明确 BM25 分数的含义与阈值范围，在统一检索出口应用过滤；低相关度应触发证据不足。

### R12 · P2 · 连续两次代词追问时，检索可能丢失原主题

这是本轮新增多轮接线的限制：query 只补最近一个用户问题。如果最近的问题本身也是代词，原主题不会进入新检索；摘要也未参与指代解析。

离线复现：历史为“quantumfold 的方法是什么？”→“它有哪些局限？”，新问题“它使用了哪些数据集？”构造的检索只有后两句，不含 quantumfold。模型虽能看到历史，检索已经先发生，仍可能无召回或召回错误主题。

定位：[dialogue.py:26](E:/codex-litprism/src/litprism/context/dialogue.py:26)。

建议：维护有证据来源的主题/论文范围或做受约束的问题改写；不能用旧回答作为新事实证据。

发现并处理：

- 较小输出预算会被推理消耗：2200 token 的一次对比调用全部用于 reasoning，正文为空；另一次解读 JSON 不完整。测试改用 8192 输出上限后解读成功。业务客户端现在识别 `finish_reason=length`，明确提示提高预算或缩小任务，不再对同一请求重复计费重试。
- 对比 prompt 原先没有完整数组类型示例，真实输出可能将一致点/分歧点作为字符串，导致按字符校验。增加完整 JSON 示例并规范化单条字符串；再次真实调用对比通过，耗时约 10.34 秒，上报 966 输入 / 1632 输出（其中 455 reasoning）/ 2598 总 token。
- UI 原先只读顶层 concepts，但 API 实际放在 analysis.concepts；修复读取路径，并用非空术语加入无窗口流程验收。
