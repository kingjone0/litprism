## 已确认的问题与改动

旧协议同时要求多条语义判断、逐字复制引文、提取结构化数值事实。真实服务多次把输出预算耗尽在推理上。简化文字说明或提高温度不能独立解决；简单 JSON 控制请求能完成，所以不能将问题概括为“服务不支持 JSON”。

本轮改为逐条复核，每次只判断一个陈述，并返回已有证据编号。服务端回填编号对应的完整原文快照，不要求模型重新抄引文或抽取事实。返回编号必须属于这条陈述的候选来源，空引用、未知引用、不完整判定不放行。旧格式的逐字引文校验保留兼容，但不再向真实模型要求复杂的引文/事实复制。

短论文又暴露了分号拆句问题：在句尾引用到来前按分号切开，会使前半句没有自身引用，退回使用整个字段的来源。现改为保留句内分号和尾部引用，提取提示词也要求逐句就地引用。单条超过 3 个来源时保持待审，不截掉其中一些再声称核查完成。

有限预算：

| 项目 | 当前边界 |
|---|---|
| 单条复核 | 单条陈述、最多 3 个来源；输入估算最多 6000 token；输出不超过用户配置与 4096 中较小值 |
| 全文差异 | 每片最多 3 条，每对最多 6 条；两两检查，包括远距批次；输入估算最多 6000 token |
| 差异输出 | 不超过用户配置与 8192 中较小值；不是无限提高预算 |
| 每次解读调用数 | 单条复核最多 48 次，全文差异最多 40 次；未覆盖项明确待审 |
| 连接与读取 | 分别最多 10 秒建立连接、60 秒读取空闲超时；这不是整篇总耗时承诺 |
| 自动重试 | 只允许一次 ConnectTimeout 安全重试；读取超时、输出截断、普通服务错误不盲重试 |
| 结构 | 复核必须完整严格 JSON；不修复残缺 JSON 后当成功 |

Requests 官方将 ConnectTimeout 标为可安全重试，参见[异常定义](https://requests.readthedocs.io/en/latest/_modules/requests/exceptions/)。程序保留安全的 HTTP 状态和异常类别，验收日志不保存凭据、任意服务错误原文或推理链正文。

较大的全文差异组仍会截断；本轮确认同一失败组在 4096 截断，8192 上限下于 4974 token 完成。测试使用 8192 输出预留，未自动提高用户现有配置；低于该额度仍可能待审。短论文不意味着所有复核都很简单。

之后的完整组合又出现过 8192 截断，所以单靠加预算不能解决。复查还发现宽泛的“寻找待限定差异”会把“性能相当”与“有约 1% 差距”当潜在冲突。最终差异任务明确为同对象/指标/条件下文本已经建立的互斥断言，以及 all/only/always 与反例互斥；不同设置、不同指标、相当但非完全相等不当矛盾。原截断组在仅修改该判定边界后于 3274 token 返回。原有逐条层仍负责对象、条件、归属、数值等源文核对，差异层不承担“证明所有可能表述完全一致”的无限任务。

## 自动质量门槛

固定集：`tools/fixtures/semantic-real-cases.json`，18 条，9 正例 / 9 对照错误陈述，来源为三篇真实论文。负例是根据真实原文构造的数字、方向、条件、单位、属性及限定词错误；PTB 与 SuperGLUE 列错配来自此前发现的真实错误类型。不能把所有负例都称为真实模型自然生成的错误。

- GPT-3 v4：物理 p.11 PTB、p.19 SuperGLUE。
- RMSNorm：14 页论文，本轮仅将首页原文用于单条测试，未称其全文通过。
- fastText：5 页论文，6 条样本作为复核提示词的留出组，随后另测完整解读流程。

来源 URL、物理页、文件 SHA256 与原文保存在 fixture。已检查实际 PDF 首页与 fastText p.3/p.4 的表格版面。PDF：

| 文献 | SHA256 |
|---|---|
| [Bag of Tricks for Efficient Text Classification v3](https://arxiv.org/abs/1607.01759) | `6cbcf620c2537ed54dfb9ed0d843a83689b82dc41dcd305bfb2e82425d4d7906` |
| [Root Mean Square Layer Normalization v1](https://arxiv.org/abs/1910.07467) | `a38ab771022fc10525d2b6b23de40307b2ca7b2bf463f5219da6a0ba1c41225f` |

门槛预先写在工具中：完整返回且没有跳过样本；负例不得被模型判支持，即使代码护栏最终挡住也不能掩盖模型误判；正例至少 80% 被支持，不能靠全部弃权通过。

最终 `final-repeat2`：**18 条重复两轮，36/36 完整返回，18/18 正例支持，18/18 负例阻止，未发现假放行**。共 28128 token，单次最大输出 1697 token，请求耗时合计 133.48 秒；36 个逻辑请求均一次连接成功。它是有限固定样本结果，不是通用准确率或稳定性保证。

此前两轮计划曾在第二轮首条调用失败；独立复测也发生过 ConnectTimeout，均保留失败记录，没有从统计中抹去。最终成功轮证明本次设置下样本能完成，不能据此宣称服务从不失败。

跨批控制集：`tools/fixtures/semantic-cross-cases.json`。两个冲突样本（SuperGLUE 同指标不同值、PTB only zero-shot 与 few-shot 互斥），两个不应误报的控制（不同指标、不同隐藏层/特征设置）。**4/4 通过**。这里故意把相互冲突的候选送入差异层，是测试而非生产中自动放行这些错误结论。

最终再加入“comparable 不等于 identical”的不应冲突控制，明确边界版本 **5/5 通过**（2 个必须检出、3 个不能误报），记录为 `cross-explicit-controls`。这是针对发现问题的开发回归集，不冒充独立盲测。

## 五页论文的实际效果与剩余边界

完整流程使用 fastText v3，5 页、22 个可索引片段。真实提取及逐条复核分别记录，不用已有生成摘要替代原文。第一次流程发现分号导致来源扩散并截断；修复后逐条层 22 条都能返回，19 条机器支持，2 条材料不足，1 条机器认为不符。

人工对照发现：该“不符”条实际涉及一个在 p.4 表格中途截断的片段，后续片段补齐了另一个隐藏层设置。不能把这次机器“不符”当作论文真的有错误；它属于上下文边界导致的误报。另有“sentiment analysis”限定没有出现在当前单一引用片段、表述中的“可复用隐藏变量”缺少相邻内容等待审情形。自动复核需要继续改善相邻证据的完整性，但本轮没有为了减少待审数而放宽护栏。

人工已对照 p.3/p.4 表格：标签预测表中 h=200,bigram 的 prec@1=46.1，Tagspace h=200 为 35.6；训练/测试时间、训练/推理加速和线程条件必须分开。原文的“可比性能”也不等于数值完全相等。全文差异层提出的候选仍需人工查双方来源，不当作数学上证明的矛盾。

“单条固定集门槛通过”“全文差异调用完成”“整篇所有陈述无需人工核查”是三件事。不会因为 18 个样本通过就把整篇标成自动质量全部通过。

最终明确互斥版本 `fasttext-explicit-final`：**19 条机器支持，3 条待审；8 个陈述片、35 组有效两两检查完整覆盖，未发现明确互斥断言，无输出截断**。最后一片只有一条，其自身不构成比较，所以不是 36 次。整体 `passed=false` 保持不变，因为仍有 3 条待审，不把完整调用覆盖等同于整篇自动质量通过。

这条最终路径的 1 次提取 + 22 次逐条复核 + 35 次差异检查，按实际原始请求追溯合计 **99429 token、465.39 秒请求耗时**；含复用结果的原始成本，不把复用当免费完成的科学判断，也不将其重复计费。与仅提取的 10737 token 相比，复核成本明显更高，尚不适合直接扩大到大量长论文。此前失败试验和控制实验不在这条单次有效路径成本内，另见 `_selftest.semantic-short/turn-usage-summary.json`；无 usage 的失败请求记为未知。

本轮停止在这篇短论文，不扩大新论文或模型。后续缺口是相邻证据完整性、误报与全文差异检查成本；没有为获得“全绿”删除待审项或降低人工入库要求。
