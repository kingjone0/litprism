# Electron 打包排障记录

2026-10-19。用户反馈"打包 Electron 时出问题，sidecar 已打包完整"。
结论：**打包链路本身是好的，失败来自启动环境**。以下是核对过程与结论。

---

## 一、当前打包链路（三步）

```
python packaging/build.py        → packaging/dist/litprism-sidecar.exe   (139 MB)
npm run pack                     → packaging/installer/win-unpacked/     (调试用，不生成安装包)
npm run dist                     → packaging/installer/LitPrism-Setup-0.1.0.exe  (247 MB)
```

产物核对（19:12 构建）：

| 产物 | 大小 | 状态 |
|---|---|---|
| `litprism-sidecar.exe` | 139 MB | ✅ PyInstaller onefile，console=True |
| `resources/app.asar` | 15 KB | ✅ 含 `desktop-electron/main.js` + `preload.js` |
| `resources/litprism-sidecar.exe` | 139 MB | ✅ 由 `extraResources` 复制到位 |
| `LitPrism-Setup-0.1.0.exe` | 247 MB | ✅ NSIS 安装包 |

Electron 依赖的 DLL 与原始 `node_modules/electron/dist` 逐项比对，**无缺失**
（`vk_swiftshader.dll` / `vulkan-1.dll` / `d3dcompiler_47.dll` 等齐全）。

## 二、真正的失败原因：`ELECTRON_RUN_AS_NODE=1`

从某些 IDE / 终端（含本项目的开发宿主）启动时，环境里带着：

```
ELECTRON_RUN_AS_NODE=1
```

Electron 见到它会**以纯 Node 身份运行**：`require('electron')` 拿不到 `app`，
于是 `main.js` 第一处 `app.commandLine` 就抛：

```
TypeError: Cannot read properties of undefined (reading 'commandLine')
```

打包后的应用没有控制台，外部看到的现象就是**双击没反应 / 一闪而过**，
很容易被误判成"打包坏了"。

**验证**：同一个 exe

| 启动方式 | 结果 |
|---|---|
| 带着 `ELECTRON_RUN_AS_NODE=1` | 立即退出，`bad option: --enable-logging` 或 TypeError |
| `env -u ELECTRON_RUN_AS_NODE` | 正常启动 |
| 资源管理器双击 | 正常（不继承该变量） |

**已加守卫**：`main.js` 开头检测 `!app`，打印可读原因并退出，
不再抛看不懂的 TypeError。

## 三、启动时序实测（正常情况）

打包版实测日志（`%TEMP%\litprism-shell.log`）：

```
19:09:33.026 sidecar path: ...\resources\litprism-sidecar.exe
19:09:33.027 spawn: ... --port 0
19:09:36.107 handshake ok: port=4188        ← 3 秒
19:09:36.489 window loaded                  ← 0.4 秒后
```

sidecar 独立启动约 2.8–15 秒（PyInstaller onefile 每次要释放 139 MB）。
`STARTUP_TIMEOUT_MS = 120000` 足够。

> 排障时踩过的一个假象：用 `| head -5` 观察 sidecar 输出会看起来"完全没有输出"，
> 因为 Python 的 stdout 在管道下是块缓冲。握手行本身有 `flush=True`，
> 走文件重定向或由 Node 读取管道都正常 —— 别用 `head` 判断它是否启动。

## 四、顺手补的一个缺陷：没有图标

构建日志里的警告：

```
• default Electron icon is used  reason=application icon is not set
```

`src-tauri/` 删除时把 `icons/icon.ico` 一起带走了，Electron 侧没配替代。
已从 git 历史取回该图标（6 个尺寸，8.4 KB）放到 `packaging/icon.ico`，
并在 `package.json` 的 `build.win.icon` 里引用。重建后警告消失。

**注意**：`signAndEditExecutable: false` 保持不变 —— 它让 electron-builder
不改写 exe 的元数据，所以**主程序 exe 的图标仍是 Electron 默认**，
只有安装包与快捷方式用新图标。要连 exe 图标一起换，得打开这个开关并确认
rcedit 在本机可用（当初关掉它就是为了绕开改写失败）。

## 五、怎么判断"打包到底坏没坏"

按顺序看这三件事，能立刻定位层级：

1. **`packaging/dist/litprism-sidecar.exe` 在不在、能不能单独跑**
   → 不在就是 `build.py` 失败（PyInstaller 阶段）
2. **`%TEMP%\litprism-shell.log` 里有没有 `sidecar path:` 这一行**
   → 没有 = Electron 根本没跑到 `main.js`（先查 `ELECTRON_RUN_AS_NODE`）
   → 有 `spawn:` 但没有 `handshake ok` = sidecar 启动失败（看它单独跑的输出）
3. **有 `handshake ok` + `window loaded`** = 壳和 sidecar 都正常，
   剩下的是页面或数据问题，不再是打包问题
