# M05 知识沉淀与产出

更新：2026-10-19。本页说明模块边界；“当前实现”与“修订目标/缺口”分开，后续实施顺序只维护在 [实现计划](../实现计划.md)。本轮只整理文档。

## 当前对象与路径

知识输入不只来自论文解读，还包括用户直接提供的知识、网页摘要/正文快照及后续研究结果。来源类型、内容范围与审核依据必须保留，不能统一改称“论文事实”。

| 输入 | 当前审核与沉淀方式 | 重要边界 |
|---|---|---|
| 六字段解读/对比的机器陈述 | 右栏绑定分析版本与陈述 ID，可修正后确认并生成独立知识快照 | 原机器结果保留；机器支持与人工确认分别记录 |
| 手工知识或网页快照 | 先 `pending`，人工核对后 `manual_confirmed` | URL 存在或搜索命中不等于正文已获取或信息真实 |
| 研究产出 | 保存草稿/报告并保留来源映射，导出时重验 | 保存交付物不自动将每句正文转成可信知识 |

```mermaid
flowchart TD
    P[论文提取候选] --> H[查看原文并填写人工核对依据]
    W[网页或用户知识快照] --> H
    H --> D{人工裁决}
    D -->|确认| K[独立知识快照及来源和版本记录]
    D -->|拒绝或暂缓| R[保留记录且不作为可信事实]
    K --> Q[进入后续可引用检索范围]
    K --> V[支持撤销并留审计]
    V --> STOP[阻止失效来源继续引用]
    A[已有研究产出及来源] --> E[导出前重新核对状态]
    E --> O[符合当前守卫才导出]
```

人工确认不是不可撤销的真理证明；来源失效、论文回收或快照撤销应影响后续问答、对比和导出。普通 QA 没有六字段同等逐条机器语义保证。

## 与修订目标的差距

现有审核接口已接通，但“提取候选一产生就可审核、机器为可选后台辅助”的完整工作流仍待补，见 [M03](03-阅读提取与协作审核.md)。主动补录机器漏提、审核分母和召回评测仍属于后续 N05/N06，不能凭知识条目数量宣称提取完整。
