# N01：阶段预算与可续验进度

2026-10-18。用户恢复功能推进后实现。适用范围是论文详情新增的“分阶段解读”；原“重新解读”、导入、对比、QA、Skill、CLI/MCP 不会因此自动获得持久续跑能力。未调用真实模型、未迁移用户主库；本轮授权主工作树提交，未打包。

## 用户操作

1. 在论文详情点“分阶段解读”，分别设置原文提取、术语提取、逐项复核、跨批核对的累计请求上限，可关闭术语。
2. 每次真实发送前先保存记录。用尽某阶段预算即暂停，原解读和术语保留；已完成请求留在本次运行中。
3. 在运行记录点“检查并恢复”，可保持或增加原预算，不能降低。成功且精确匹配的请求直接复用，不新增发送或重复累计用量。
4. 失败/进程中断请求默认不重发。需要时勾选“允许重试失败或结果未知的请求”；这些请求可能已经计费，重试及受影响的后续生成仍占用累计上限。
5. 刷新页面或重新打开应用只读取运行记录，不自动恢复调用。进程仍在执行时重复启动会被拒绝；进程退出后操作系统释放运行锁，允许检查恢复。

默认上限为提取 12、术语 12、逐项 48、跨批 40。每阶段允许 0–1000 的整数；这是请求次数预算，不是金额保证。既有语义安全上限仍有效，逐项最多 48，跨批默认 40（可受启动环境的原有上限设置影响）；恢复重放的检查也占本轮语义算法遍历额度，不重复计为新的 API 发送。增大累计预算不绕过这些安全限制。

`completed` 表示本次提取覆盖完整、六字段机器复核通过且未记录术语错误，仍不等于人工确认或全文无遗漏。`partial` 表示仍有未覆盖、待审或术语错误。`paused_budget`、`needs_retry`、`failed`、`cancelled`、`stale` 分别表示预算暂停、需确认重试、失败、取消和版本失配。

## 安全恢复与一致发布

恢复绑定原文题录/块 ID/物理页/文本哈希、当前分析哈希、实际模型和客户端协议类型、端点、temperature、max_tokens、timeout、JSON 模式、上下文配置、复核上限及 Python 实现指纹。源码版本或来源发生变化，拒绝复用，需新建运行。密钥不进入绑定；轮换密钥本身不作为输出参数变化。

本次运行内部按请求序号、阶段及完整 messages 哈希匹配响应。只复用本次运行内的精确成功记录，不共享给其他论文或其他运行，不把回放算成新的独立语义质量样本。显式重试可能改变上游输出；下游请求哈希变化时重新生成，旧分支响应不被套用，原尝试记录仍保留。

新工作流关闭 OpenAI/Anthropic 客户端内部的自动重试和 response_format 降级重发，每个发送尝试先落库。失败尝试不退还预算；网络中断或进程退出可能留下 `started`，按结果和费用未知处理。旧调用入口的传输行为保持兼容。成功响应是模型返回的结构化 JSON，不存 API Key、请求头、异常正文或推理链；usage 只保留允许的数值字段。

任务使用跨进程文件锁避免同一运行重复执行。最终发布前在同一 SQLite 事务里复核来源和分析版本、更新运行分析哈希、替换分析与术语；中途外部改动不能被覆盖。取消是协作式，已发送的远端请求可能继续执行；返回的成功响应可先落库，后续不再发新请求。

普通任务队列仍不跨应用重启保存；持久的是分析运行及调用记录。重新打开后须从论文详情检查恢复，不能把旧 task_id 当永久句柄。尚未为旧入口补造持久恢复能力，也未验收冻结安装包中的实现指纹。

## 数据、API 与用量

schema v7 增加 `analysis_runs` 和 `analysis_run_calls`，v6 升级保留已有分析；不重写旧块 ID。测试使用临时库，应用使用独立 `LITPRISM_HOME`，不能为读取配置而打开用户主库迁移。

| API | 行为 |
|---|---|
| `POST /api/paper/{pid}/analysis-runs` | `{budgets: {extract, concepts, semantic_review, semantic_cross_review}, with_concepts: true}`；字段可省略使用默认；返回 run_id/task_id |
| `GET /api/paper/{pid}/analysis-runs` | 最近 30 个持久运行，含状态、阶段、各阶段消耗、用量、是否需确认重试 |
| `GET /api/analysis-runs/{rid}` | 安全运行明细及请求序号/尝试/结果类型，不透出原始请求/响应 |
| `POST /api/analysis-runs/{rid}/resume` | `{budgets: {...}, retry_failed: false}`；预算只能不减；任务执行前验证版本 |
| `GET /api/tasks/{tid}` / `POST /api/tasks/{tid}/cancel` | 复用既有轮询/取消；运行状态需看 task.result.status，不把任务成功等同论文通过 |

每次实际尝试只累计一次。成功重放不增加 `_coverage.usage`；语义子计在 `_semantic_review.usage`，不可与总计再相加。失败和中断计入 spent；未上报用量明确 `unknown_usage_calls`，输入/输出显示已报告值，不能将未知当免费。最终分析保存 `_analysis_run_id`；暂停/失败时用量仍能从运行记录读取，不污染原分析。
