## 一、最初要解决什么

最初产品目标是个人研究者的论文知识助手：导入论文→核验真实性→结构化解读与知识整理→带引用追问→跨论文对比→扩展阅读与知识积累。核心底线是“不编”：真实性核验、原文检索与引用回溯、导入守卫不能为了界面或自动化而削弱。

需求来源为[早期需求映射](design/设计文档.md)、[桌面方案及修订记录](design/方案定稿.md)和[界面与扩展设计](design/界面与扩展设计.md)。原文包含先后被替代的决策；以下对照既保留最初目标，也记录后来明确的取舍，不把所有历史提议都当成当前承诺。

### 原始 13 项核心需求对照

“已有实现”仅表示有代码路径和相应回归，不表示所有真实材料已通过学术质量验收。

| 原始编号 | 最初需求 | 当前实现 | 剩余工作/验收 |
|---|---|---|---|
| 1 | 导入 PDF 等论文格式 | PDF/DOCX/HTML/TXT/MD/TeX，题录补全、核验后入库 | 复杂版式、公式/表格专项集；无文本层转写暂停 |
| 2 | 提取论文核心信息 | 六字段解读、全文目标计划、超窗分批、提取闸门与有界语义复核 | 当前新流程的真实完整论文验收、漏读与成本控制 |
| 3 | 文献分类 | 标签、分组/嵌套分组、领域字段、主题簇 | 分类效果与管理交互边界；不能将生成领域分类当作核验结论 |
| 4 | 知识点梳理 | 结构化笔记、产出编辑与导出、人工知识快照 | 完整阅读标注、一般质量验收及实际用户库恢复演练 |
| 5 | 专业术语解释 | 独立术语提取、详情/术语表与原文引用 | 未获与六字段解读同等的逐条语义保证；真实术语质量需验收 |
| 6 | 跨论文关联 | TF-IDF 相似度、共享术语/主题簇、关联列表 | 仅是线索；未实现原设计的完整引用网络与图谱交互 |
| 7 | 问答与深度追问 | RAG、范围守卫、历史/摘要/偏好预算、引用和来源右栏、失败轮次记录 | 真实长会话保持、自动回取旧句柄、流式显示 |
| 8 | 多篇论文对比 | 从原文取证、论文归属检查、维度/一致点/分歧点、有界语义与人工审核 | 真实多文献验收；同字段比较不等于跨字段全量一致性 |
| 9 | 推荐与扩展阅读 | 学术来源检索、推荐/核验与题录导入 | arXiv 已可自动取全文；非 arXiv 自动下载和推荐质量仍待验收 |
| 10 | 准确、客观、符合学术规范 | 提示词约束、结构/引用闸门、待审隔离、人工纠正 | 这是持续质量目标，不能标为“已保证”；需固定样本和人工证据 |
| 11 | 避免虚假文献与无依据发挥 | 三层防线、失效来源复核、无证据拒答、引用/导出守卫 | 检查之外仍可能误判或漏判；不能把引用存在当作语义正确 |
| 12 | 确认检索文献真实存在 | 多源核验、五态、原自动结果与人工放行分别留痕 | 数据源失败/不收录不能判虚构；真实接入可用性持续验收 |
| 13 | 检索结果进入本地库 | 自动核验通过或人工确认后导入 | arXiv 可下载解析，本地可补全文；非 arXiv 自动取得正文未完成 |

## 二、哪些设计被保留、替代或暂缓

| 主题 | 最初/中间方案 | 当前决策与实现 |
|---|---|---|
| 外壳 | Tauri + Python sidecar + NSIS | 由于本机实测问题改为 Electron + 同一 Python 内核；不重迁移 Tauri；F3 暂停 |
| 本地模型管理 | 早期提出 Ollama 列表/拉取/删除及硬件提示，随后转向 API | 当前以云端 API 提供商为主要路径；代码保留兼容入口，不代表完整本地模型管理器已实现，本轮不部署模型 |
| embedding | 原二期提出向量/RRF 混合检索，多次讨论本地或 API | 当前仍为词法检索与查询扩展；按用户决定不增加本地 embedding，不自动重启该方向 |
| 扫描件 | 本地 OCR→多模态 API 的多轮选型 | D3 暂缓；不能把设计、探针或建表当成已提供可靠转写 |
| Skill | 固定内置任务与开放框架间多轮调整 | 以最终声明式框架为准：内核能力与 Skill 分开、不执行任意代码、不做无限工具循环；不是必须补早期固定技能列表 |
| MCP | 讨论内外部服务，最终一期只对外 | 已有 Server/工具内核，完整 stdio/选模/生命周期仍待验收；不把外部 MCP Client 自动放回一期 |
| 上下文与记忆 | 简单压缩；曾提出记忆一期只建表 | 后续已实现上下文内核、显式偏好、三层映射与冻结轮次；自动隐式学习不在当前范围 |
| 复核协作 | 逐条小片段机器复核作为主流程 | 修订目标为可选全文批量辅助、人工可直接裁决；机器开关、能力感知全文批量、提取完成后复核前候选持久化及直接人工确认/撤销已接通；复杂来源质量仍待验收，见 [当前设计与流程图](当前设计与功能流程图.md) |
| 解读原文策略 | 固定字符截断→完整分批→固定全文前缀配合范围指令 | 全文装得下则固定前缀，多指令取指定真实范围；装不下则完整分批；二者均需独立语义核查 |
| 来源与可信知识 | 早期侧重论文引用和核验徽章 | 按后续要求扩展为回复来源链接→右栏论文/知识/网页原文→人工审核/修正入库/撤销 |
| 通用网页 | 早期不直接使用搜索结果作事实，后来设计双层证据和 W1–W3 | 已有 Tavily 摘要候选和人工快照审核；自动获取全文、答后入库与证据编排仍未完成 |
| 生成式回复 | `lit-ui` 白名单组件、四级降级、规划流式展示 | 组件与数据库回填已有实现；逐 token 流式尚未实现，不能连同其余组件一起标完成 |
| 交付目标 | 早期“内核可用后尽早装壳打包” | 现在先完成证据、质量和兼容性；源码可运行不代表安装包已交付或最新 exe 已生成 |

决策演变解释为什么有些最初条目不继续实现。没有被明确取消、但尚无实现的桌面体验或数据安全能力仍需登记，不能悄悄从计划中消失。

### 原桌面设计中容易遗漏的条目

对照 `desktop-electron/main.js` 和当前工作流，仅登记现状，不启动实现：

| 最初要求 | 当前可确认内容 | 保留的欠账 |
|---|---|---|
| 主窗口/设置窗口、记住尺寸与位置 | 有主 BrowserWindow 和应用内设置；尺寸为初始配置，未见 bounds 持久化流程 | 窗口尺寸/位置记忆；独立设置窗是否仍必要待确认，不能默认再造一个窗口 |
| 托盘、最小化托盘、打开/退出菜单 | 当前桌面入口未见 Tray 实现 | 是否纳入首个正式安装版需产品确认，未实现 |
| 导入/解读完成的系统通知 | 有界面任务反馈与 toast，未见 Electron 原生 Notification 流程 | 系统通知及点击后定位，不把 toast 算成系统通知 |
| 原生拖入文件路径 | 当前文件拖放通过 Web 上传/后台任务处理 | 原生路径方案已改变；不能宣称 Rust 原生拖放已完成，无需为复刻实现细节另开路线 |
| 设置页迁移数据目录、带校验备份 | N08 已有在线快照、完整预检、新目录恢复/复制、重启切换及取消 | 用户实际库和跨机器演练；密钥不随备份迁移，不承诺热换库 |
| 无网启动和本地使用 | 有本地存储、界面和 mock 路径 | 无网安装版完整场景需验收；真实模型和在线核验仍需网络，不能承诺完整离线研究 |

## 四、后续新增的质量工程如何纳入总计划

这些不是抛弃原需求另造产品，而是为“准确、可追溯、可积累”补齐实现条件。

| 增量 | 当前落地 | 还缺什么 |
|---|---|---|
| 物理页与表格恢复 | 单页分块、保持顺序、保守恢复、复杂区待核对 | 复杂真实语料与公式/表格语义验收，旧 PDF 需重导入 |
| 任务范围与提取闸门 | 真实 chunk/字符区间、完整消息预算、有界修复、未覆盖单元 | 密度/推理倍率校准；条数达标不能证明事实覆盖 |
| 句内来源与相邻补足 | 来源编号选择、同论文下一片段、去重、固定 ID | 长句、跨页表格与来源额度的更多真实反例 |
| 逐条与同字段差异 | 严格 JSON、预算/截断待审、按字段报告、失败影响范围 | 长文成本、跨字段冲突、风险选择与覆盖口径；不得靠缩范围假称全量通过 |
| 用量与任务状态 | 解读/对比各阶段已报告用量、未知提示、协作取消；单篇 N01 新入口持久运行/恢复和失败尝试归因 | 其他旧入口统一接入、真实费用核对；不承诺远端即时停止或撤费 |
| 人工知识闭环 | 版本绑定陈述审核、修正/确认/拒绝/撤销及独立知识快照 | 主动补录、同源质量面板已有；完整阅读标注和持续评测仍欠 |
| 数值签名与评测工具 | 机械数值原型、现有审核记录聚合工具 | 原型尚未接入生产；已采集漏提占比不是真实召回，接受率不是事实精度 |

## 五、建议实施顺序与完成标准

以下按实际进展更新工作队列；N01 已实施，后续依赖和付费验收条件仍须满足。不承诺日程或凭空给出工时；每一项按前置条件与验收产物收口。

### 前置链路现状与剩余缺口

来源发现与材料取得不是 P 系列之后的步骤，模块说明见 [M01](modules/01-来源发现与候选.md) / [M02](modules/02-论文与网页资料入库.md)。已有学术检索/去重/题录核验、统一候选暂存与筛选、arXiv 全文获取、本地文件解析、网页摘要待审、材料完整度，以及 N12 内容去重/版本绑定。非 arXiv 正文由用户上传；普通网页正文抓取、复杂 URL 分流与候选到材料的完整事件历史仍缺。搜索到、题录已入库、全文已取得与知识已确认须分别表示。

这些缺口映射到现有 N09/W1–W3 及数据管理工作，不另起一套任务编号，也不因整理文档就自动恢复外部服务接入。材料完整度已有字段及提示，但当前“只读取已索引材料”的 P 计划不能独立证明原 PDF 已完整取得和解析。后续何时实施仍按用户推进。
