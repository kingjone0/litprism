# 文献棱镜 LitPrism · 一期实现计划

> 日期：2026-10-16 · 状态：执行中
> 原则：**数据结构与不变量的优先级最高** —— 它们决定后续所有功能的实现方式，改起来最贵。
> 策略参数（阈值、预算）先用校准值起步，实现后按实测标定。

---

## 一、排序原则

```
第 1 优先  ████████  数据结构 + 不变量 + ref 系统
第 2 优先  ███████   上下文管理内核（Meter/Policy/Summarizer/Seam/恢复）
第 3 优先  █████     记忆系统（三层 + 不可变轮次 View）
第 4 优先  ████      内核增量（白名单/人工确认、Skill 框架、扫描件转写、交付物、MCP Server）
第 5 优先  ███       界面（三栏 + GenUI 渲染层）
第 6 优先  ██        外壳（Tauri + sidecar 打包）
```

**为什么这个顺序**：第 1–3 步做完，就能在 CLI 上跑通「导入 → 核验 → 解读 → 多轮问答 →
压缩 → 还原」的完整链路，且所有关键不变量都有测试覆盖。界面和外壳是包装，
放在最后不影响正确性，也避免在数据结构还在变的时候返工前端。

### D4 交付明细

| 文件 | 内容 |
|---|---|
| `deliverables.py` | 交付物存储（类型/状态受约束）+ Markdown/JSON 导出 + 引用来源附出 |

**核心约束**：导出必须带出 `## 引用来源`（paper_id / page / tag / chunk_id）——
**没有引用清单的交付物是不可追溯的**，读者看到结论却不知道来自哪一页，比不写更糟。

**状态流转**：`draft` → `exported`（导出时自动推进）；`final` 不降级。

**端到端实测**：Skill → 交付物 → 导出全链路。导出文件里能看到
回答标的是 `[P1 p.1]` / `[P2 p.2]`，而引用来源段显示实际片段在 `p.5` / `p.4` ——
**矛盾对读者一目了然**，这正是带出引用来源的价值。

### 阶段 C 的三条硬边界（可执行，不靠提示词）

1. **记忆不得作为事实依据** —— `detect_memory_as_fact()` 扫描
   "根据我的记忆…""你之前说过…"这类表述
2. **记忆不得作为引用来源** —— `validate_citations()` 拒绝 `[mem_xxx]` 形式的引用
3. **事实性内容不得进记忆层** —— `assert_memory_preference_only()` 拒绝非偏好类 kind

第三条是**写入侧的守卫**：防止有人把"论文事实"塞进记忆层，从而绕过核验流程。
这是记忆系统与防幻觉体系之间最容易出现的漏洞。

**测试抓出的问题**：测试自己踩了去重的坑（8 条相同内容被合并成 1 条），
说明去重逻辑是对的、测试写错了 —— 顺手补了一条专门的去重测试。

**测试抓出的真实缺陷（阶段 B，共 3 个）**：

1. 保留预算（30% 窗口）覆盖整个上下文时，noop 理由误报为"找不到安全切口"——
   实际是"无需压缩"的正常状态。两种 no-op 必须区分。
2. **检查点被重复计价** —— 压缩块与它的替换消息是同一份摘要的两种表示，
   测量时两者都算了一次，导致用户看到"摘要占 13%"而账本说"压到 6%"的矛盾数字。
   修复：替换消息已可见时跳过块节点。
3. `Meter.measure` 的 SQL 漏选 `block_id`，导致上述去重逻辑在真实调用路径上失效
   （单测用内存数据所以没暴露，端到端才抓到）。

   计入 system，导致用户看到"系统提示词占了 40%"的假象
