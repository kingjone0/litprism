prepare 在读取凭据前校验 PDF 哈希/页数，保存源副本、解析块、解析告警与版本清单；run 校验源、控制集、代码、模型/协议、参数和阈值。调用前独占写 started 标记；中断后再次 run 被拒绝，不自动重复费用未知的请求。每次请求先保存记录，再发送；生产流程经过 N01，客户端内部重试关闭。report 只读取本地结果，不加载凭据或补发请求。

连接、读取等待和输出额度是三件事。新增 `LITPRISM_REVIEW_CONNECT_TIMEOUT` 可显式改变复核连接等待，默认仍为 10 秒；它与已有读取等待都受用户 `llm.timeout` 上限约束，并纳入 N01 恢复绑定。本轮实验配置只影响相应进程，没有修改用户全局环境或日常设置。

## 预设质量门槛

1. 18 个固定正反例必须全部执行完整：负例错误放行 0，正例支持至少 80%；另报正例被阻止、明确误判不符及弃答数。
2. 5 个差异控制必须完整，错误数 0，区分“同指标互斥”与“不同指标/设置无需冲突”。
3. 论文提取/差异覆盖完整、机器待审 0，才能通过机器链路门槛；未覆盖和未知不算 0，也不能算通过。
4. 生成陈述须有版本绑定的独立评定，全部已评定且无错误放行/误拒后，才能通过整体质量门槛。没有评定的陈述计入 unjudged；模型自判 supported 不替代参考答案。未采集漏提分母时召回为 null，不冒充 100%。

这些控制集是已有开发回归样本，不是新盲测。论文机器通过、控制集通过、独立评定通过分别报告；任一不完整不得称整体通过。评定文件标识 reviewer、analysis_hash、陈述文本哈希、判定与原文依据，只用于离线评估，不触发知识库人工确认。

## 产物与复现

质量命令按请求范围返回退出码：未通过为 1，通过为 0；controls_only 通过只表示控制集通过，summary 的整篇 `quality.passed` 仍为 false。失败样本保留 ID、异常类别、HTTP 状态（如有）、底层异常类别、实际连接/读取与输出设置；全部控制例各尝试一次，不因单个请求异常抹去该样本或重复收费。报告标记自身实现指纹，原始运行摘要另行保留。
