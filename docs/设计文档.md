## 三、防幻觉机制（核心设计）

这是本项目与"直接用大模型读论文"最本质的区别，共三层。

### 第 1 层 · 文献真实性核验（`verify.py`）

**多源交叉验证**：同一篇论文同时查询 Crossref、OpenAlex、arXiv、Semantic Scholar（可选），
每条候选记录按标题相似度打分，取最优；来源越多、相似度越高，可信度越高。

**四态判定**：

| 判定 | 触发条件 | `exists` | 是否允许引用 |
|---|---|---|---|
| `verified` | DOI 精确命中，或 相似度 ≥ 0.92 且有年份/作者佐证 | True | ✅ 可以 |
| `likely` | 相似度 ∈ [0.82, 0.92) | True | ⚠️ 需人工确认 |
| `not_found` | 数据源正常响应，但无记录达到 `likely` 阈值 | False | ❌ 禁止 |
| `unchecked` | 所有数据源请求失败（断网/限流） | False | ❌ 禁止 |

**两个关键决策：**

1. **必须区分 `not_found` 与 `unchecked`。**
   网络故障时若返回 `not_found`，会把真实论文误标为"虚构"——这比"漏检"更严重，
   因为它会让用户对真实文献产生怀疑。因此代码里 `sources_ok` 为空时一律判 `unchecked`。

2. **标题相似度必须对词序敏感。**
   早期版本用"词集合 Jaccard"，导致 `"Attention Is All You Need"` 与
   `"Is Attention All You Need?"` 得分 1.00（词集合完全相同），把同名异文当成同一篇。
   现改为三个信号加权融合：

   ```
   score = 0.75 × max(字符级序列相似度, 词序列相似度) + 0.25 × 词集合 Jaccard
   若短标题是长标题的连续子串且占比 ≥ 0.6 → score = max(score, 0.94)   # 副标题
   ```

   实测：词序颠倒 → 0.91（落入 `likely`）；加副标题 → 0.94；完全不同 → 0.21。

**核验的可信度还依赖"标题质量"。** PDF 首页常有版权声明、arXiv 页眉、期刊模板套话，
朴素地"取第一行"会把 `"Provided proper attribution is provided, Google hereby grants permission to..."`
当成标题。因此：

- 用 PyMuPDF 的字体信息，取首页**字号最大**的文本行作为标题候选（论文标题几乎总是最大字号），
  并用噪声正则过滤版权/页眉/页脚；
- 再通过 `enrich.py` 用 arXiv / Crossref / OpenAlex 的**权威题录**校正标题、作者、年份，
  并把"哪些字段来自数据库"明确记录在 `verify_evidence` 与 `doc.meta` 中，不静默篡改。

### 第 2 层 · 检索增强问答 + 引用回溯（`agents.QAAgent`）

三道闸门：

1. **只给片段**：检索到的原文片段带编号（`[P1]`）和页码（`p.3`）交给模型，
   系统提示明确禁止使用片段之外的知识。
2. **无依据拒答**：召回为空时直接返回"本地知识库中没有检索到相关片段"，
   并提示可能原因，而不是让模型"合理推测"。
3. **引用回溯校验**：回答产出后，`parse_citations()` 解析所有 `[P# p.##]`，逐条检查：

   | 检查项 | 拦截的幻觉 |
   |---|---|
   | 片段编号是否存在于本次召回 | 引用 `[P9]` 但只提供了 8 个片段 |
   | 标注页码是否等于该片段实际页码 | 片段在第 3 页却标注 `p.88` |
   | 回答有实质内容却没有任何来源标记 | 通篇无依据的自由发挥 |

   任一不通过 → `citation_check_passed = False`，在 CLI 与 Web 上显式告警：
   "引用校验未通过：回答中可能存在无法追溯或虚构的来源标记，请以原文片段为准。"

**页码为什么可信？** 分块时逐行携带真实页码（`Section.lines: list[(page, line)]`），
每块的页码取该块**首行的真实页码**，而不是章节起始页。早期版本用章节首页，
导致 GPT-3 论文所有片段都显示"第 2 页"——这会让引用校验失去意义。

### 第 3 层 · 导入守卫 + 全量留痕

- `import_record()` 拒绝 `not_found` / `unchecked` 的文献进入本地知识库，
  防止未核验内容污染后续检索与问答；
- 每次核验写入 `verify_log` 表（查询、DOI、标题、完整结果 JSON、判定、置信度、时间），
  可审计、可复现；
- 缓存层（`data/cache/`）保留原始数据库响应 7 天，便于复核判定依据。

## 四、数据模型（`db.py`）

| 表 | 作用 | 关键字段 |
|---|---|---|
| `papers` | 论文元数据 | `doi`(唯一索引)、`title`、`authors`、`year`、`verify_status`、`verify_level`、`verify_evidence`、`fingerprint`(标题+年份去重) |
| `chunks` | 正文分块 | `paper_id`、`page`、`section`、`text` |
| `chunks_fts` | FTS5 全文索引 | `seg_text`（对 CJK 逐字空格分词，使中文可检索） |
| `analyses` | 结构化解读 | `research_question`、`methodology`、`experiment_design`、`key_conclusions`、`innovations`、`limitations`、`field`、`keywords`、`payload` |
| `concepts` | 术语表 | `term`、`definition`、`category` |
| `relations` | 跨论文关联 | `paper_a`、`paper_b`、`rel_type`、`score`、`evidence` |
| `verify_log` | 核验审计 | `query`、`result`(JSON)、`level`、`confidence` |

**中文检索方案**：SQLite FTS5 的 `unicode61` 分词器不切分中文。
本项目在入库前用 `cjk_segment()` 在每个汉字两侧插空格，使每个汉字成为独立 token；
查询时同样处理，并把连续汉字合成**短语**（保证字序，`"方法论"` 不会匹配到 `"法论方"`）。

## 五、跨语言检索（`query.py`）

BM25 是词法检索，中文问题直接匹配英文正文必然失败。两层扩展：

1. **内置中英学术词表**（确定性、零成本）：约 200 组术语双向映射，
   如 `方法论 → method / methodology / approach`、`few-shot → 少样本`。
   同时抽取关键词（英文去停用词；中文取 bigram 并剔除含功能字的噪声 bigram）。
2. **LLM 查询改写**（可选）：让模型把问题改写成 5~10 个中英检索关键词，失败时静默回退。

扩展后的多个查询用 `OR` 组合成一条 FTS5 表达式，由 BM25 排序决定相关性。

> 踩坑记录：早期把整句问题当作 `AND` 连接的所有词，导致
> `"What training data and optimization settings were used?"` 零召回
> （需要 8 个词同时出现在同一块）。改为 OR + BM25 排序后正常。
> 另外 token 未清洗时 `used?` 里的 `?` 会触发 `fts5: syntax error`，
> 现改用白名单只保留字母数字与 CJK。

## 六、结构化解读（`extract.py` + `prompts.py`）

**上下文装配**：按章节重要性排序（摘要 → 引言 → 方法 → 实验 → 结果 → 讨论 → 结论 → 局限），
拼装标题、作者、年份、摘要与各章节正文，超预算按字符截断并标注。

**提取字段**：`research_question`、`methodology`、`experiment_design`、`key_conclusions`、
`innovations`、`limitations`、`field`、`keywords`、`field_notes`。

**提示词的硬约束**（对应"避免过度简化或主观臆断"）：

- 每个字段只写该论文**实际表述**的内容，不补全、不推测、不美化；
- 原文未给出的字段填空字符串，并在 `field_notes` 说明原因；
- 数字、指标、数据集名称、模型名称必须与原文完全一致；
- `innovations` 只写作者明确声称的贡献，不写模型评价；
- `limitations` 优先采用作者自述，作者未提及则留空。

**术语解释**：要求先给出术语**在本论文语境下**的含义；若文中未定义，
必须写"（论文未给出定义）"并标注后续内容为"通用含义"。

## 七、对比与推荐

### 对比（`CompareAgent`）

把各论文的结构化解读按 `[P1]…[Pn]` 编号送入模型，产出六维度对比矩阵
（研究问题 / 方法论 / 实验设计 / 关键结论 / 创新点 / 局限）+ 一致点 + 分歧点。
提示词要求：某篇在某维度无信息时填"未提及"，不猜；分歧点需说明可能来源
（任务设定 / 数据集 / 指标差异）；**不得评选"哪篇更好"**，除非用户明确要求且能给出量化依据。

### 推荐（`RecommendAgent`）

**候选来源全部是数据库检索结果，模型只负责写推荐理由，不允许新增条目。**

| 策略 | 来源 | 适用 |
|---|---|---|
| `openalex_related` | OpenAlex `related_works` | 给定种子论文找同主题簇 |
| `citing` | OpenAlex `filter=cites:<id>` | 找后续工作（追踪领域演进） |
| `keyword` | Crossref + OpenAlex + arXiv 关键词检索 | 只有研究方向时 |
| `local` | 本地库 BM25 | 找库内相关论文 |

每条候选都带 `verification` 字段说明其存在性依据；`--import` 可把通过核验的候选
一键导入本地知识库（继续用于问答与对比）。输出末尾附免责说明：
检索结果反映数据库收录情况，不代表文献质量或与用户方向的绝对匹配度。

## 八、已知局限与后续方向

**局限**

- 扫描版 PDF 无文本层，需先 OCR（导入时给出明确警告）。
- 章节识别基于标题词典，无小标题的短文会退化为单节。
- 跨语言检索依赖内置词表；冷僻领域术语可能召回不足。
- 跨论文关联用 TF-IDF 词法相似度，只是**线索**，不做语义判断。
- `not_found` ≠ "编造"：新预印本、小众期刊、非英文文献可能尚未收录。

**后续可做**

- 接入 `sentence-transformers` 做语义向量检索，与 BM25 做混合排序（接口已预留）。
- 增加 Zotero / BibTeX 双向同步。
- 用引用网络做领域演进时间线可视化。
- 对核验结果引入人工确认闭环（把 `likely` 的人工判定回写数据库，形成本地白名单）。

## 九、验证记录

端到端实测（3 篇真实 arXiv 论文：`1706.03762` Attention、`1810.04805` BERT、`2005.14165` GPT-3）：

| 验证项 | 结果 |
|---|---|
| PDF 解析与题录补全 | 标题/作者/年份全部校正正确（arXiv 权威题录） |
| 真实性核验 | 3 篇均 `verified`，相似度 1.00，多源命中 |
| 虚构论文核验 | 构造标题 → `not_found`，提示"不得当作真实文献引用" |
| 分块与页码 | 42 / 61 / 286 块；页码跟随真实位置（p.1 摘要、p.2 方法、p.10 结论） |
| 中英跨语言问答 | 中英文提问均能召回正确片段 |
| 引用回溯校验 | 正常回答通过；伪造 `[P9 p.3]` 与错误页码 `[P2 p.88]` 均被拦截 |
| 文献推荐 | 种子论文推荐出 ViT / MAE / ESM / CLIP 等真实高被引论文，全部 `verified` |
| 单元测试 | 49 项全部通过 |

> 测试期间发现并修复的真实缺陷：词序不敏感的相似度算法、`?` 导致的 FTS5 语法错误、
> 整句 AND 检索导致零召回、章节合并导致页码丢失、"Intro text." 被误判为标题、
> `best_match` 为空时 `message` 属性崩溃。
