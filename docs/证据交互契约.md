## 回复与右栏

- 回答正文保留引用编号，回复后附可点击的来源链接。每轮链接绑定稳定的 chunk/source id，不根据当前轮的 P 编号猜测旧轮来源。
- 点击来源后在右侧显示：类型（论文/知识条目/网页）、标题、作者或发布地址、页码或“无页码”、原文片段、可信等级和审核依据。模型输出不决定这些字段。
- 链接在重开会话后继续可用。来源被回收、撤销或删除时显示当前失效状态，不静默换成其他来源。
- 长文显示分块覆盖清单；“本批未读取”不等于“原文未提及”。分批抽取后只拼接已验证内容，暂不自动补写跨批结论。

## 可信状态与人工加入

| 来源 | 初始状态 | 可否进入知识库回答的事实证据 |
|---|---|---|
| 论文 | 原有五态核验 | 只有自动核验通过或人工确认；保留二者区别 |
| 网页搜索结果/粘贴网页片段 | 待审核候选 | 否；可展示候选链接与搜索摘要，不能伪装成已审核知识 |
| 用户知识条目 | 待审核候选 | 否；用户在右栏检查内容后填写依据、确认加入 |
| 人工确认后的网页/知识 | 人工确认 | 是；仍显示原始类型、地址和人工依据，不改称自动验证的论文 |
| 被拒绝或撤销的知识 | 不可引用 | 否；保留审核历史，旧回复链接显示失效状态 |

确认绑定标题、地址与原文快照的内容哈希。变更内容应产生新候选，不能沿用旧审核。审核、拒绝和撤销均由后端记录时间、动作与依据。

网页搜索先保存供应商返回的摘要快照；明确标注它不是网页全文，也没有论文核验。没有搜索服务凭据时明确报不可用，不返回假数据。网页 URL 只作来源标识或用户主动打开，默认不抓取任意地址。

## 约束

- 用户偏好仍只影响表达，不能通过这套来源入口混入偏好层；事实知识有独立存储与审计。
- 范围绑定到论文的会话不会自动混入全库知识；只有全库会话检索已人工确认的知识条目。
- 下载和生成守卫重新读取当前来源状态；来源撤销后，引用清单不能继续将其标成可用。
- 人工确认表示用户接受这份快照，不等于内容客观真实。语义质量仍需审核与实际原文核对。

## 必须验证的路径

1. 回复后来源链接 → 右栏正确原文和出处；深浅主题、窄窗口、键盘操作、会话重开。
2. 待审核网页/知识不能被 QA 引用；右栏确认后可检索，撤销后停止召回。
3. 旧哈希或重复审核不能静默覆盖；论文来源保持既有核验规则。
4. 不同来源的 P 编号只在各轮内有效；数据库 id 才是链接和复查依据。
5. 网络失败、无密钥、候选无结果与模型失败分别显示，不以假来源补齐界面。

## 当前解读与对比的补充约束

- `whole` 表示全文原文作为固定前缀，不表示只有一次模型调用。各指令绑定实际 chunk 或字符区间；`batched` 才表示按窗口分批送入。界面显示的是已索引原文送达，不是内容理解率。
- 页码为物理页。相邻原文补足仍使用真实 chunk ID、同论文归属，并占用每条至多三个来源的额度；右栏候选链接须与服务器来源集合一致，不能硬编码仅有一个来源。
- 语义复核目前覆盖解读六字段与对比。跨批报告按同字段比较范围记录 `fields_done`、`fields_pending` 和 `skipped_claim_ids`，不表示跨字段全量一致性已核查。
- `coverage.error=call_budget` 明示整体调用预算耗尽；`output_limit` 是输出/推理预算耗尽。未执行的检查保持待审，不能因为 HTTP 成功或原文覆盖完整而放行。
- 人工语义审核使用 `analysis_hash + claim_id`；confirm 需 `reviewed_text` 与 `note`。确认生成独立知识快照，原始机器结论不被覆写，论文真实性状态不因此变化；旧版本写入返回冲突。
- 原文高亮只帮助定位，不能作为模型引文或语义判定的证明。人工审核同时查看标题、物理页、条件、数字和差异双方。
- `_coverage.usage.complete` 仅指服务用量上报完整，不是语义通过。UI 展示“已报告”用量及未知调用；模型未报告缓存字段时不能显示虚假的 0% 命中。

上述路径已经过最新一轮无窗口本地 API/UI 验收；真实网页服务、真实长论文整体质量和重启后的任务续跑不在这个结论内。最近实测 743 项回归，本轮仅补文档，未重复执行。
