## 原文如何进入模型

`reading.py` 固定序列化 P 编号、原文、标题、页码和 chunk ID。消息先放原文，任务指令放尾部；各次请求仍是独立调用，并非共享模型会话状态。

`plan.py` 按连续章节和估算陈述密度分配任务：

1. 全文连同系统提示、原文标签、目标范围副本、消息封装及修复提示可装入窗口时，使用 `whole`。多条指令共享同一全文前缀，每条指令只提取指定范围。
2. 超长章节按真实 chunk 分配；过长的单 chunk 使用原文字符区间 `[start, end)`，从 0 起计数，连续且不重叠。区间原文附在任务尾部，避免让模型在全文中自行数字符。
3. 每条指令的 token 与期望条数按该范围计算。当前配额为 `max(1, floor(max_tokens × 0.7 / (64 × 9)))`；密度约 4.5 条/千输入 token。这些是经验参数，不保证不截断、无漏读或无重复。
4. 真实消息装不下或完整表格行无法按配额切分时回退 `batched`，沿原文顺序完整分批，不用生成摘要替代尾部原文。无法容纳一条完整表格行时可明确报预算不足。

固定前缀只创造缓存复用条件，是否命中由服务上报；没有缓存字段时显示未知。全文可见不保证引用正确、注意力均匀或多次生成一致，跨批/跨指令复核仍有必要。

`gates.py` 检查结构、引用、数字文本、条数区间和既有引用问题。条数低于估算下限时最多重跑两次，保留更好的候选；超限或修复后仍失败记录到未覆盖单元。条数检查是风险提示，不是覆盖真值。输出截断不自动无限重试或重规划。

## 语义复核、差异与人工审核

服务器生成陈述 ID 和来源候选，模型只返回判定、理由和已有证据编号；服务器回填存储的原文，不让模型重新生成原文。相邻补足只取同论文的下一片段，且占用每条最多三个来源的额度；不是任意扩展检索。

| 范围/参数 | 实际行为 |
|---|---|
| 保证范围 | 解读六字段与对比；术语、QA、Skill 不因此自动具有同等逐条语义保证 |
| 候选陈述 | 提取后在内存形成 `_candidates`（确定性 ID，与复核结果同一套编号），整体末尾才落库，关闭复核后的直接确认仍缺 N03 接线 |
| 单条复核 | 至多三个来源、完整严格 JSON；**模型能力已知时一次核对多条，并复用提取阶段的全文序列化前缀**（批量由内容与窗口决定，不写死条数）；能力未知的旧入口仍为每次一条、输入估算最多 6000 token |
| 调用数 | 能力已知时不再设人为上限（批量由窗口决定，仍受客户端 `remaining_calls` 约束）；能力未知的旧入口保持逐条 48 次 / 跨批 40 次 |
| 差异范围 | `by_field_tile_pairs`；能力已知时一个 tile 按半个窗口装（240 条可同片），跨批与较近片优先，不跨字段穷举。能力未知时仍为每片三条 |
| 差异含义 | 同对象/指标/条件下明确互斥断言的候选；不同条件或“性能可比但数值不完全相同”不应自动当冲突 |
| 失败范围 | 跨批一次输出截断只影响该对，连续三次才停止后续；成功会复位连续计数，总失败另记；一般传输/格式错误仍可使任务失败 |
| 整体预算 | 支持客户端提供 `remaining_calls`；耗尽不发后续复核请求，返回不完整报告。普通客户端没有因此自动获得“整篇最多 12 次”的限制 |
| 完成判定 | 存在陈述、无待审、当前检查范围覆盖完整才可能 `passed=true`；仍只是机器结论，不是全文学术质量证明 |

逐条结果为 `machine_supported`、`needs_review` 或 `contradicted`。未复核、证据不足、冲突或覆盖不足不会作为正常结论进入正文。不能把“不支持”自动理解为论文错误：可能是片段不完整、模型误判或来源数量超限。

右栏可同时查看被引及相邻原文、页码、机器理由和差异双方；句子高亮只是定位辅助。人工确认必须填写核对依据与修正后的正文，绑定分析哈希和 claim ID，创建独立知识快照，保留原分析与论文核验状态；旧分析版本的提交被拒绝。拒绝、撤销及来源失效有记录，导出与生成重新检查可引用性。

机械数值索引的 `clause_signature` 原型目前在 `tools/proto_numeric_index.py`，未接入生产 `make_units`。生产保留兼容的 `facts/value_index` 路径；当前提示词不要求抽取 facts，不能把原型收益当作所有数值事实已完成自动核查。

## 来源、数据与模型配置

论文使用 `verified` / `manual_confirmed` / `likely` / `not_found` / `unchecked` 五态，只有前两者可引用。网页/知识快照使用 `pending` / `manual_confirmed` / `rejected` / `revoked`；机器语义支持不改变这些人工可信状态。

回复的 P 编号只在该次请求内有意义，历史链接使用稳定 chunk/source ID。回收或撤销后，旧链接显示失效，不替换成其他来源。原文页码是 PDF 物理页，不保证与印刷页码一致。旧 PDF 需重导入才能获得新解析；旧分析需重跑，不自动改写历史 chunk ID。

schema 增量：v4 为 `evidence_sources/chunks/reviews`，v5 为 `semantic_runs/reviews`，v6 为提供商及模型的 `window_tokens`；v7 新增 `analysis_runs/analysis_run_calls`；v8 新增模型最大输出能力、API 能力缓存与每次调用参数记录；v9 材料完整度；v10 统一候选池；v11 人工漏提补录；v12 材料快照、块/分析绑定及历史分析归档。以 `schema.py` 为单一迁移入口，不为读取凭据而通过 KnowledgeBase 打开用户主库。

桌面设置可选择 OpenAI Chat Completions 或 Anthropic Messages 协议、提供商和启用模型。Key 由 SecretStore 管理，Windows 默认使用 DPAPI，库内存引用；跨平台弱存储降级会明确标注，Base64 混淆不能称为加密。不得复制真实凭据到文档。未配置真实模型时使用明确标注的 mock；已选提供商缺少模型/凭据时明确报错，不静默回退。

模型能力只读展示：获取模型目录时保留 API 的明确上下文/最大输出字段与更新时间，API 缺项使用已确认默认值。当前公开目录实查 Flash 返回 `context_length=1000000`、没有最大输出；输出按用户确认的 384000 token。不提供窗口、任务输出额度或输出预留编辑控件；已知能力的 Web 提取/复核/聊天在发送端自动分配，旧逐项 4096、差异 8192 不再截断此自动路径。未知能力的旧入口仍为兼容路径，不当作已自动接通。

保留 P 系列全文前缀与范围指令，不扩大本轮为输入重构或配额修复。N01 保存实际请求额度；Chat 在完成后展示服务独立返回的思考，不入证据、引用或下一轮事实输入。完整公式、只读目录实查、等待策略、schema 与验证边界见 [模型能力与思考展示](模型能力与思考展示-2026-10-19.md)。本轮没有追加真实生成验收，原整篇未通过结论不变。

旧入口的有界复核保留一次安全连接超时重试及受限的 response_format 兼容回退；普通业务调用还有其他重试路径。N01 与 N02 明确关闭内部重试，每次尝试分别记录；不能将某个入口的策略概括为所有任务均不重试。

CLI `Ctx.llm`、独立 MCP 与 Web 的 ProviderStore 选模路径尚未全面统一；桌面选模不会保证自动改变每个 CLI 工具。测试工具须说明自身读取哪份配置，不能打开主库试错。

## 结果字段与 API

| 字段 | 如何解读 |
|---|---|
| `_coverage` | 已索引原文送达、whole/batched、计划、提取闸门、未覆盖单元、窗口、用量；不是模型理解率 |
| `_citation_check` | 来源编号、页码、状态等机械检查；不是引文蕴含结论的证明 |
| `_semantic_review` | 机器陈述、来源、差异候选、待审与阶段覆盖；未执行模型标 `not_run` |
| `_citations` | 绑定实际 chunk ID 的引用清单；重复 tag 去重，导出重新读取当前来源状态 |
| `_batch_notes` | 未经同等语义核查的生成备注，不能作为正常事实证据 |
| `_coverage.usage` | 生成、修复、术语、逐条及跨批的逻辑调用用量；语义报告另有语义阶段小计，二者不能相加重复计费 |

用量保留服务上报值。`unknown_usage_calls` 非零表示总计不完整；`failed_calls` 包括截断等失败调用。未上报不代表免费，也不沿用前一次 usage。`complete` 只描述用量上报完整性，与提取/语义的 complete 不同。缓存比例仅覆盖有缓存上报的调用，不等于最终费用或所有 HTTP 尝试的账单。旧入口致命失败时不保证保存部分用量；N01 新入口将每次尝试持久落库，可在运行记录查看，失败不覆盖旧分析。

| API | 用途/约束 |
|---|---|
| `GET /api/candidates`、`POST /api/candidates/{id}/status` | 统一候选池：按 kind/status/query 筛选；状态流转 |
| `POST /api/candidates`、`POST /api/candidates/sync` | 手动补充候选；把候选池与知识库对账（命中即 `imported`） |
| `POST /api/candidates/{id}/import` | 候选导入知识库：有 arXiv 走取全文，否则只导题录且必须过核验 |
| `POST /api/candidates/{id}/fetch` | arXiv 直链取全文：下载→解析→核验→入库→回链候选（仅 arXiv 主机） |
| `POST /api/providers/{id}/active` | 选用模型；成功后自动刷新一次能力目录，返回 `capability_refreshed` |
| `GET/POST /api/evidence` | 候选列表/创建；新建知识或网页不自动可信 |
| `GET /api/evidence/{ref}` | 按稳定 ID 取得真实来源和当前状态 |
| `POST /api/evidence/{ref}/review` | 知识/网页 action、note、content_hash；论文人工放行走既有白名单逻辑 |
| `POST /api/evidence/search` | Tavily 搜索摘要候选，缺密钥/服务错误明确失败；不自动抓取 URL 全文 |
| `GET /api/paper/{pid}/semantic` | 当前解读哈希、陈述、来源与审核历史 |
| `POST /api/paper/{pid}/semantic/{claim_id}/review` | action、note、analysis_hash；confirm 还需 reviewed_text |
| `GET /api/semantic-runs/{rid}` | 对比语义结果、分析哈希、来源与审核历史 |
| `POST /api/semantic-runs/{rid}/{claim_id}/review` | 对比的版本绑定人工审核，参数与单篇审核相同 |
| `POST /api/tasks`、`GET /api/tasks/{tid}`、`POST /api/tasks/{tid}/cancel` | 开始、轮询及协作取消；不跨重启持久化 |
| `POST/GET /api/paper/{pid}/analysis-runs` | 单篇分阶段解读的新入口/最近 30 个持久运行；创建返回 run_id/task_id |
| `GET /api/analysis-runs/{rid}`、`POST /api/analysis-runs/{rid}/resume` | 读取安全运行明细/核对版本后恢复（**阶段调用预算已取消**）；成功精确复用，失败或中断须显式允许重试 |

sidecar 模式除 ping 等豁免入口外，API 需 `X-LitPrism-Token`；`run.py serve` 是另一种启动模式。以上不是远程多用户权限系统。
