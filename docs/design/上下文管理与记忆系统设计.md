## 一、核心判据（先立这条）

参考文档里最重要的一句话，我认为应该刻进这个项目的 README：

> **每一次压缩，是在「窗口位置」上动手，还是在「新增量」上动手？**
>
> - 在**窗口位置**上动手 = 阈值到了就重写历史 → 前缀作废、损失随轮次复利衰减、单粒度、模型无参与。
> - 在**新增量**上动手 = 只压「上次压缩之后新增、且已被任务消费掉」的部分 → 前缀不变、  
>   每份内容一生只折一次、可分级、模型可参与。

**LitPrism 取后者。** 而且我们的场景有一个天然优势：**"已消费"的边界是清晰可判的** ——  
一轮问答结束后，那一轮检索到的原文片段就已被消费完；论文解读生成后，用于解读的正文片段也已完成使命。  
不像编码 agent 需要靠工具配对来判断工作集边界。

## 二、上下文管理

### 2.1 架构

```
┌──────────────────────────────────────────────────────────────┐
│  Transcript（append-only 事件日志）                            │
│  messages 表即天然 transcript；压缩 = 追加事件，永不原地改写     │
└───────────────────────────┬──────────────────────────────────┘
                            │ 派生
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  Surface（渲染视图）                                           │
│  计算「哪些事件当前可见」；遮蔽/替换在此体现                     │
└───────────────────────────┬──────────────────────────────────┘
                            │ 询价
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  Meter（测量服务）—— 所有决策的唯一定价来源                     │
│  totalTokens / surfaceTokens / perNodeTokens                  │
└───────────────────────────┬──────────────────────────────────┘
                            │
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  Policy（触发 + 选择）                                         │
│  触发：增长门控 / 压力兜底 / 人工 /compact                     │
│  选择：保留最近 N；受保护区硬排除；安全切口                     │
└───────────────────────────┬──────────────────────────────────┘
                            │ 候选区间
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  Summarizer（摘要后端，可替换单点）                             │
│  输出必须通过「收缩验证」才能提交                               │
└───────────────────────────┬──────────────────────────────────┘
                            │
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  Seam（提交事务，单一写入口）                                   │
│  start → summary → replacement → end，附不变量前置校验          │
└───────────────────────────┬──────────────────────────────────┘
                            │
                            ▼
┌──────────────────────────────────────────────────────────────┐
│  Projections / Telemetry                                       │
│  用量 / 压力 / 构成分解 / 压缩账本                              │
└──────────────────────────────────────────────────────────────┘
```

**四个照抄的架构决定：**

1. **append-only transcript + 派生视图**。压缩 = 追加一条「替换」事件，不就地改写 `messages`。  
   好处：回放确定性、可审计、可撤销。反例是"遍历消息数组就地替换成摘要字符串"——  
   一旦有第二个消费者（UI / 遥测 / 导出）就会崩。
2. **单一测量服务**。所有决策读同一个 `measure()`，UI 的占用率只是它的另一个消费者。  
   **不做第二套 token 估算。**
3. **摘要后端可替换**。策略（何时压/压哪段/留多少）与摘要实现（本地小模型 / 远端 / 模板）解耦。
4. **单一写入口 + 前置不变量**。见 2.8。

### 2.2 数据模型

```sql
-- append-only 事件日志（消息本身就是事件）
CREATE TABLE messages (
  id              TEXT PRIMARY KEY,
  conversation_id TEXT NOT NULL,
  seq             INTEGER NOT NULL,       -- 名义化事件序号，非负安全整数
  ref             TEXT NOT NULL,          -- 稳定可打印引用，固定宽度零填充：m00123
  role            TEXT NOT NULL,          -- user | assistant | system
  content         TEXT,
  -- LitPrism 特有：结构化附件（引用片段、GenUI 组件）
  citations       TEXT,                   -- JSON：引用片段（含 chunk_id / paper_id / page）
  citation_check  TEXT,                   -- JSON：引用回溯校验结果
  kind            TEXT DEFAULT 'normal',  -- normal | compact-checkpoint
  meta            TEXT,
  created_at      TEXT,
  UNIQUE (conversation_id, seq)
);
CREATE INDEX idx_messages_ref ON messages(conversation_id, ref);

-- 压缩块（摘要单元）
CREATE TABLE compaction_blocks (
  id                  TEXT PRIMARY KEY,
  conversation_id     TEXT NOT NULL,
  tier                INTEGER DEFAULT 1,   -- 1=消息区间（本项目不做 2/3，见 2.11）
  topic               TEXT,                -- 短标题，供检索与展示
  summary             TEXT NOT NULL,
  direct_refs         TEXT NOT NULL,       -- JSON：直接覆盖的消息 ref
  effective_refs      TEXT NOT NULL,       -- JSON：传递性覆盖的全部原始 ref（血统）
  created_at          TEXT,
  survived_count      INTEGER DEFAULT 0,   -- 存活轮次（老化用）
  active              INTEGER DEFAULT 1,   -- 是否渲染进上下文
  shadowed_token_count INTEGER NOT NULL,   -- 被遮蔽的定价 token 数
  -- LitPrism 特有：被折叠区间涉及的引用片段清单（正文可折叠，句柄必须留）
  citation_handles    TEXT                 -- JSON：[{chunk_id, paper_id, page}]
);

-- 压缩事务（先立据再干活）
CREATE TABLE compaction_tx (
  id              TEXT PRIMARY KEY,        -- compactionId
  conversation_id TEXT NOT NULL,
  source_command  TEXT,                    -- 触发来源：nudge | pressure | manual | overflow
  owner_turn      TEXT,
  status          TEXT NOT NULL,           -- started | summarized | committed | failed | busy
  start_seq       INTEGER NOT NULL,
  end_seq         INTEGER NOT NULL,
  failure_code    TEXT,                    -- 闭集，见 2.8
  created_at      TEXT,
  updated_at      TEXT
);

-- 压缩账本（可观测性）
CREATE TABLE compaction_ledger (
  id                TEXT PRIMARY KEY,
  conversation_id   TEXT NOT NULL,
  block_id          TEXT,
  shadowed_tokens   INTEGER,
  summary_tokens    INTEGER,
  repriced_tokens   INTEGER,               -- 本次折叠造成的重付（简化版 compRepay）
  created_at        TEXT
);
```

**ref 设计要点**（踩坑最多的细节）：

- 固定宽度零填充 `m00123` —— 让正则与排序都简单；
- 解析时**容忍非规范形态**（`m123`、带围栏、大小写），**输出永远规范**；
- **自动纠正写反的 start/end**（模型经常写反）；
- 解析失败给**可操作**错误，而不是「invalid input」。

### 2.3 测量（Meter）

```
measure(conversationId) → { totalTokens, surfaceTokens, nodes[] }
estimateMessage(message)  → tokens
```

- `totalTokens` = 会话记账（含已被压缩的原文，下降慢）
- `surfaceTokens` = 发送视图（压后实际发给模型的大小）
- `nodes[].tokens` = 逐节点定价（用于算"压哪段能省多少"）

**必须区分这两种占用**，并在 UI 上分别展示。混用会让用户以为压缩没生效。

**估算启发式与偏差**：无 tokenizer 时用 `4 字符/token`，每块 +4 开销。  
**必须写进 UI 与文档**：该启发式对 **CJK 严重低估（可能低 2–4 倍）**。  
LitPrism 是中英混排场景，这个偏差尤其明显 —— 中文界面上要明确标注"估算值"。  
优先复用**提供方上报的真实用量**，条件是「最新成功调用的请求 envelope 与待测 envelope 完全匹配」，  
否则完全估算。

### 2.4 触发（三层，互相独立）

```
# 层 1：增长层（日常主力，绝对 token，与窗口大小无关）
step       = 30000                      # LitPrism 校准值，比参考的 50000 小
growthGate = max(12000, 0.45 * step)
可压缩增量 = 自上次锚点以来新增、且已被消费的 token
if 可压缩增量 >= growthGate and 摘要质量达标: trigger(nudge)

# 层 2：压力层（窗口百分比，兜底）
if usage >= 0.75 * W:  trigger(nudge)
if usage >= 0.95 * W:  trigger(nudge + emergencyTruncate)

# 层 3：人工（常备逃生门）
/compact          # 无参：按策略自动选区间
/compact --dry-run  # 只报告会压哪段、预计省多少
```

**为什么增长层用固定绝对值**：若只按百分比，首次压缩的绝对位置 ≈ 开机占用 + 一个步长，  
窗口越大触发越晚。固定步长让长会话在任何窗口档位下都持续得到压缩。

**LitPrism 的校准差异**：参考值 50000 是为编码 agent（单次工具输出动辄上万 token）标的。  
我们的单轮内容量小得多，取 **30000** 起步，实现后再按实测标定。

**溢出恢复必须是独立路径**：

```
on requestError where code == CONTEXT_WINDOW_EXCEEDED:
    compact(trigger="overflow")     # 绕过常规阈值与保留策略
    if surfaceGeneration advanced: return RETRY     # 只在视图确实前进后重试
    # 限次：maxOverflowRetries = 1
```

### 2.5 选择（压哪一段）

```
selectCompactable(conv) -> Range | null:
    nodes = surface.nodes
    # 1) 永不动前缀头（system message）
    firstIdx = 1 if nodes[0] is system else 0
    # 2) 从尾部向前累计保留预算
    acc = 0; keepFrom = len(nodes)
    while keepFrom > firstIdx and acc < retainTokens:
        keepFrom -= 1; acc += nodes[keepFrom].tokens
    # 3) 向前回退到安全切口
    while keepFrom > firstIdx and not balancedBefore(nodes[keepFrom]):
        keepFrom -= 1
    if keepFrom <= firstIdx: return null        # 静默 no-op，不写日志
    return { start: nodes[firstIdx], end: nodes[keepFrom - 1] }
```

**三个不可妥协的点**：

1. **system message 永不遮蔽**（遮蔽它等于重写整个前缀）；
2. **绝不切断 tool-call / tool-result 配对**；
3. **找不到安全段就返回 null，什么都不做** —— 静默 no-op 比"压出一堆碎片"好得多。

#### 受保护区（LitPrism 版）

| 保护对象                                    | 理由                     |
| --------------------------------------- | ---------------------- |
| system message                          | 前缀稳定 + 防幻觉约束载体         |
| **第一条用户消息**                             | 研究意图。丢了整段会话失去锚         |
| **最后一条用户消息**                            | 当前指令                   |
| 最近 5 条 / ~5K token                      | 活跃工作集（硬地板）             |
| **当前轮的引用片段**                            | ⭐ LitPrism 特有：正在被引用的证据 |
| **引用片段的句柄（chunk_id / paper_id / page）** | ⭐ 永不折叠 —— 这是可追溯性的最小载体  |
| 压缩块自身的 checkpoint 消息                    | 它装着摘要本身                |
| 交付物生成任务的源范围                             | 正在生成中的综述/对比报告，其依据不能被折掉 |

**注意"引用片段"的保护是分层的**：**正文可折叠，句柄必须留**。这样既控制上下文增长，  
又不破坏可追溯性 —— 需要看原文时按 `chunk_id` 从数据库取回（见 2.6）。

**高频内容绝不做全历史保护** —— 这是上下文无界增长的头号成因。

### 2.6 恢复（LitPrism 的天然优势）

参考文档把可逆性分三级，**LitPrism 免费拿到 L2**：

| 级别                 | 能力                 | LitPrism 的对应                 |
| ------------------ | ------------------ | ---------------------------- |
| L0 不可逆             | 摘要是终态              | —                            |
| L1 可寻址还原           | 按块 / 按区间还原，可还原到文件  | 实现：`/restore <blockId>`      |
| **L2 内容寻址 + 按需取回** | 超大内容换占位符，按 id 取回全文 | ⭐ **我们的 `chunks` 表就是内容寻址存储** |

**关键洞察**：论文原文本来就已经完整存在 SQLite 的 `chunks` 表里，并且有稳定的 `chunk_id`。  
所以压缩时**不需要把原文塞进摘要或占位符** —— 直接记 `chunk_id` 句柄即可，  
需要时一条 SQL 就取回。这是 LitPrism 相对通用 agent 的结构性优势：**原文从未真正离开系统。**

因此：

- 折叠时写入 `compaction_blocks.citation_handles`（句柄清单，体积极小）
- 提供 `/restore <blockId>` 还原摘要块
- 提供 `/restore <blockId> --to-file` —— **把全保真原文写盘，而不是灌回上下文**  
  （保住前缀缓存的关键技巧，也天然契合我们已有的导出能力）

**别指望模型自发恢复**：参考文档实测，模型不会自己想到调用恢复工具。  
所以要么在指令里强制（如"综述定稿前先还原核对"），要么不承诺。**一期不承诺自动恢复**，  
只提供人工入口，并在文档里说明。

### 2.7 摘要

**产物形态**：一次压缩 = 一条 `kind = compact-checkpoint` 的 user 消息替换整个选定区间。

```
content = [
  CHECKPOINT_PREAMBLE + "\n\n" + "<compacted-summary>",
  ...摘要正文,
  "</compacted-summary>"
]
```

`CHECKPOINT_PREAMBLE` 措辞（可直接复用）：

> 这是自动生成的检查点，用于压缩此前的一段对话以释放上下文。  
> 把其中记录的内容当作既定背景，在此基础上继续，不要复述。  
> 直接从后续消息继续任务，不要提及本检查点。

**为什么要 preamble + 显式围栏**：preamble 防止模型花 token 评论"我看到一个摘要"；  
显式围栏让下游（人、审计脚本、另一个模型）能机械识别摘要边界。

**收缩验证（不可省）**：

```
if framedSummaryTokens >= shadowedTokens:
    reject("摘要比被遮蔽内容还长")
```

没有这一步，会偶尔得到"压缩后上下文变大"。配套做法：把结果反馈给模型让它重写。

**摘要该保留什么**（参考生产审计的保留率）：

| 内容类型            | 保留率 |
| --------------- | --- |
| 精确值（指标、数据集名、超参） | 93% |
| 消息 / 块引用        | 47% |
| 带位置的引用（论文 + 页码） | 39% |
| 方法名 / 模型名       | 16% |

⇒ **在摘要指令里显式要求：数字与指标逐字保留、引用必须带 chunk_id 与页码、  
决策保留"为什么"、约束逐条列出。** 这是最便宜的质量改进。

**LitPrism 特有的摘要约束**：摘要中**不得产生新的文献论断**。  
摘要只是压缩已有内容，不能成为新的事实来源 —— 否则压缩就成了绕过防幻觉的后门。

### 2.8 提交事务与不变量

```
begin:
  校验不变量
  append compaction/start        (同步，先立据)
  prepare summary                (异步，可能失败)
  重新校验（区间是否仍有效）
  append compaction/summary
  append replacement message
  append compaction/end
finally:
  释放准入
```

**失败码闭集 + 可操作文案**：

| code             | 文案要点                     |
| ---------------- | ------------------------ |
| `busy`           | 本会话有正在进行的压缩              |
| `cancelled`      | 已取消                      |
| `changed`        | 选中的历史在替换前发生了变化，尝试已记录     |
| `summary`        | 无法产出有用摘要（或未通过收缩验证），尝试已记录 |
| `commit`         | 未干净完成，部分历史可能已变，重试前请检查状态  |
| `overflow_limit` | 溢出恢复已达重试上限               |

**不要用 `Error` 抽象一切。** 每种失败都要能被上层分类、被用户理解、被遥测聚合。

#### 核心不变量（一期实现这 8 条）


1. `compactionId` / `sourceCommand` 必须非空
2. 所有 `seq` 必须是非负安全整数
3. `shadowedRefs` 非空，且 `shadowedRange.start/.end` 等于其首/末
4. `shadowedRefs` 必须**完整、按序、连续**枚举该区间的每一个可见节点
5. 替换事件的 `sourceEventRefs` 必须包含**每一个**被遮蔽的可见节点
6. 任何切口不得切断 tool-call / tool-result 配对
7. 已有未闭合事务时不得再开一个
8. **成功的 `end` 必须恰好伴随一个 `summary`**

⭐ **LitPrism 特有第 9 条**：**压缩不得改变引用校验的结论。**
即：对同一问题，压缩前后基于该区间得到的引用校验结果必须一致。
压缩只改变"原文在不在上下文里"，不改变"引用是否成立"。

**载体设计**：把校验器做成**可单独运行的服务**，而不是散在业务代码里的 `if`；
**双重校验**：载入期（配置）+ 提交前（事件）；错误文案写清「哪条规则、哪个 seq、为什么」。

#### 配置 fail-fast 清单（载入期拒绝）

- 未知配置键
- 保留比例 ≥ 阈值比例
- `retainRatio` 与 `retainTokens` 同时给出（互斥）
- 保留预算 ≥ 触发阈值
- 重试次数为非正数
- 预算算式 `W - O - B <= 0`

反过来，"畸形配置不该破坏正常默认值"的可选字段应**静默丢弃 + 一次警告**，而不是整块拒绝。
**区分这两类是配置设计的核心判断。**

### 2.9 可观测性

**三层投影（最低配）**：

| 投影 | 内容 | 用途 |
|---|---|---|
| `tokenUsage` | uncachedInput / output / cacheRead / cacheWrite | 计费与趋势 |
| `contextPressure` | 提供方上报的真实 prompt 规模 / 预计规模 / 窗口 | 触发决策与 UI 占用 |
| `contextBreakdown` | system / 引用片段 / 摘要 / 对话 | 「上下文由什么组成」 |

**LitPrism 的构成分解要特别标注"引用片段"占比** —— 这是本项目最大的一块上下文消耗，
用户需要看到它。

**简化的 miss 归因**（参考文档的三类分解，我们砍到两类）：

```
missed     = max(0, cur.input - cur.cached)
growth     = max(0, cur.input - prev.input)
newContent = min(missed, growth)              # 正常新增，不是问题
compRepay  = missed - newContent              # 压缩造成的重付（含无法归因部分）
```

参考文档把 `compRepay` 与 `ttlRepay` 分开，但那需要知道"最早待结算折叠起点"。
LitPrism 是单机单用户、调用间隔长、缓存收益本就不高，
**简化为一类并如实标注"含无法归因部分"** —— 不要假装能精确归因。

**单次折叠损益**（回答"这次压缩回本了吗"）：

```
T     = 本次折叠造成的重付 token（只计一次）
sigma = 摘要本身 token
S     = 被遮蔽的 token（每轮省下的量）
breakevenTurns n* = T / max(1, S - sigma)
paidBack = 已发生轮数 >= n*
```

**状态面板应包含**：两种占用、构成分解、块清单（id / 覆盖 token → 摘要 token / 年龄）、
可压缩区间（带尺寸）与受保护区（标明 BLOCKED 及原因）、压缩账本。

### 2.10 前缀缓存

LitPrism 是单机低频调用，缓存收益远低于编码 agent（后者活跃期缓存读取占比 94%）。
但**有两条仍必须遵守**：

1. **稳定系统锚点**：系统提示词在最前面且**逐字节稳定**。
   任何"按轮次变化的措辞"要么追加在**尾部**，要么做幂等哨兵包裹。
   ⭐ 这条与我们的提示词设计直接相关 —— **禁止在系统提示词里插入动态内容**（如"当前时间"）。
2. **尾部追加式指令**：简洁指令追加到 system prompt **尾部**，绝不前置。

**如实告知用户**：本项目的压缩是**改写式**（替换历史区间），
从第一个被改动 token 起前缀复用失效。所以压缩的主要成本是**重付前缀**，
而不是摘要那点输出 token。这个事实要写在设置页里，不藏着。

### 2.11 明确砍掉的部分（及理由）

参考文档面向的是长时间运行的编码 agent，LitPrism 场景不同。**以下不实现，并记录理由**：

| 砍掉 | 理由 | 何时需要加回 |
|---|---|---|
| **tier-2/3 多代分级** | 会话长度不足以触发；我们的会话以"一次研究任务"为单位，很少超过几十轮 | 若出现单会话数百轮的重度使用 |
| **漂移重锚（reconcile）** | 不适用：我们完全控制消息序列化，不存在客户端重发历史 | 若将来支持外部客户端接入 |
| **双压缩冲突检测** | 不适用：本项目只有一套压缩器 | 若将来引入第三方压缩 |
| **wire 层工具注入 / 车道头 / URL 前缀** | 不适用：我们不是中间层代理，没有宿主原生压缩 | 不适用 |
| **miss 三类归因的完整恒等式** | 单机低频，收益不抵复杂度 | 若用户报告缓存成本异常 |
| **内容寻址存储的"永不设上限"** | 我们天然满足（原文在 `chunks` 表） | 已满足 |
| **紧急截断的完整实现** | 一期只保留最简硬截断并计数 | 若触发次数非 0 |

**这个取舍要写进文档**，避免后人看到"参考文档有而我们没有"就以为是漏了。

## 三、记忆系统

### 3.1 三层记忆的映射

`dsh-mnemon` 把记忆分三类。映射到 LitPrism：

| dsh-mnemon | LitPrism 对应 | 到达方式 |
|---|---|---|
| **Runtime memory**（偏好、工作约定） | 研究方向、术语偏好、表达偏好、常用分组 | 每轮**注入**，紧凑（≤500 token） |
| **Project Documents**（设计、调查、流程） | 解读笔记、交付物、阅读批注 | **先搜后读** |
| **Memory Spaces**（持久事实、实体关系） | ⭐ **知识库本身就是 Memory Space** | 按需召回 |

**这个映射很自然**：LitPrism 的知识库（论文 + 解读 + 术语 + 关联）天然就是它的长期事实层。
不需要再建一个平行的记忆存储。

### 3.2 数据模型

```sql
-- 常驻记忆（每轮注入，必须紧凑）
CREATE TABLE memories (
  id           TEXT PRIMARY KEY,
  kind         TEXT NOT NULL,   -- research_interest | term_preference | style_preference | misc
  key          TEXT,            -- 可选键，如术语原名
  value        TEXT NOT NULL,
  source       TEXT NOT NULL,   -- explicit（用户明说）| derived（系统推断，二期）
  confidence   REAL,
  pinned       INTEGER DEFAULT 0,   -- 是否常驻注入
  created_at   TEXT,
  updated_at   TEXT,
  last_used_at TEXT
);

-- 轮次记忆视图（不可变，pin 到该轮）
CREATE TABLE turn_views (
  id              TEXT PRIMARY KEY,
  conversation_id TEXT NOT NULL,
  turn_seq        INTEGER NOT NULL,
  -- 本轮读写了什么（供 turn memory bar 展示与审计）
  read_refs       TEXT,          -- JSON：本轮注入/检索到的记忆与片段
  written_refs    TEXT,          -- JSON：本轮写入的记忆
  resident_tokens INTEGER,       -- 本轮常驻部分占用
  retrieved_tokens INTEGER,      -- 本轮按需检索部分占用
  created_at      TEXT
);
```

### 3.3 策略：分层驻留 + 投影预算

借鉴 `Layered strategy` 与 `Projection Budget`：

```
每轮上下文组装：
  ① 常驻层（eager）     研究方向 / 术语偏好 / 表达偏好      预算 ≤ 500 token
  ② 按需层（on demand） 解读笔记 / 交付物 / 知识库召回        共享剩余预算
  ③ 组装成不可变 View，pin 到该轮
```

**常驻层必须有硬上限**（对应 `light-context` 的"共享上限"思想）。
常驻记忆无上限增长，会持续挤压检索片段的预算 —— 而检索片段才是回答质量的关键。

**常驻层的准入标准**：只有"几乎每轮都用得上"的才常驻。
拿不准的一律放按需层 —— 宁可多一次检索，不要每轮白付 token。

### 3.4 不可变轮次 View

**每轮检索到的记忆固化为一个不可变 View**，pin 到该轮。好处：

- **一致性**：该轮上下文在生成过程中不会漂移
- **可审计**：`turn memory bar` 展示"本轮到底读写了什么"
- **可复现**：同一轮重放得到同样的上下文

界面上：每条回复下方一行小字，如
`本轮读取：3 条偏好 · 8 个片段 · 2 篇论文解读`，点击展开明细。

### 3.5 写入：一期只做显式

**一期只支持 `source = 'explicit'`** —— 用户主动标记（对应 `dsh-mnemon` 的"一键保存"），
或手动添加。

**不做隐式推断。** 理由：隐式记忆容易记错，用户又不知道系统记了什么，破坏透明性；
且一旦记错会持续污染后续输出，很难发现。

**写入流程**（借鉴"去重、蒸馏"）：

```
用户标记 → 交给模型：去重（是否已有同类记忆）→ 蒸馏（压缩成一句话）→ 归类 → 写入
         → 回执说明去向（新增 / 更新了哪条）
```

隐式推断留到二期，且前置条件是"记忆可见、可编辑、可删除"的完整界面已就位。

### 3.6 信任模型与硬边界

`dsh-mnemon` 的原则是「记忆历史永远不能凌驾于当前指令之上」。
**LitPrism 需要更强的一条**：

> **记忆不得凌驾于防幻觉约束之上。**

具体三条硬规则，写死在框架层（不是靠提示词请求）：

1. **记忆只能影响表达偏好**（用词、详略、排序），**绝不能影响事实判断**。
   禁止出现"根据我的记忆，这篇论文……"这类表述。
2. **记忆内容不得作为引用来源。** 记忆是"用户说的"，不是"文献说的" ——
   混淆两者等于新开一条幻觉通道，而且比模型幻觉更隐蔽，因为它看起来"有据可依"。
3. **记忆不得改变任何核验结论。** 用户说"这篇我确认过"不能替代白名单里的留痕确认流程。

## 四、两者如何配合

```
                    ┌─────────────────────────┐
                    │  记忆系统                │
                    │  常驻层（偏好）           │
                    │  按需层（笔记/交付物）     │
                    └───────────┬─────────────┘
                                │ 注入 / 检索
                                ▼
   ┌────────────────────────────────────────────────────┐
   │  上下文组装（每轮）                                  │
   │  系统提示词（逐字节稳定）+ 记忆 + 检索片段 + 历史     │
   │  → 固化为不可变 View，pin 到该轮                     │
   └───────────┬────────────────────────┬───────────────┘
               │ 询价                    │ 超预算
               ▼                        ▼
   ┌───────────────────┐    ┌──────────────────────────┐
   │  Meter            │───▶│  Policy（触发 + 选择）     │
   │  totalTokens      │    │  增长门控 / 压力 / 人工     │
   │  surfaceTokens    │    └──────────┬───────────────┘
   └───────────────────┘               │ 候选区间
                                       ▼
                          ┌──────────────────────────┐
                          │  Summarizer + Seam        │
                          │  收缩验证 → 事务提交       │
                          └──────────┬───────────────┘
                                     │ 句柄（chunk_id）
                                     ▼
                          ┌──────────────────────────┐
                          │  chunks 表（内容寻址存储） │
                          │  按需还原 / 还原到文件     │
                          └──────────────────────────┘
```

**三个接口点**：

1. **记忆 → 上下文**：策略决定什么常驻、什么按需、预算多大；
2. **上下文 → 压缩**：Meter 定价，Policy 决策，Seam 提交；
3. **压缩 → 记忆**：折叠产生的摘要块与引用句柄，成为可检索的历史证据。

## 五、对一期范围的影响

| 模块 | 排期 | 说明 |
|---|---|---|
| append-only transcript + 派生视图 | **一期** | 数据结构层，必须早做（改数据模型代价高） |
| Meter（测量服务） | **一期** | 单一实现，UI 复用 |
| Policy：三层触发 + 受保护区 + 安全切口 | **一期** | 含 `/compact` 人工入口 |
| Summarizer + 收缩验证 | **一期** | 摘要后端可替换 |
| Seam（事务 + 9 条不变量 + 失败码闭集） | **一期** | 工程质量的核心 |
| L1 还原 + 还原到文件 | **一期** | 复用 `chunks` 表，工作量小 |
| 可观测性（三层投影 + 简化账本） | **一期** | 状态面板 |
| 记忆系统：常驻层 + 不可变 View + 显式写入 | **一期** | 三层记忆的常驻与按需两层 |
| 记忆系统：隐式推断 | 二期 | 需先有完整可见/可编辑界面 |
| tier-2/3 多代分级 | 不实现 | 见 2.11，会话长度不足以触发 |

**工程量提醒**：上下文管理这套东西比看上去重 —— 但其中**数据结构与不变量必须早做**，
因为它们决定了后续所有功能的实现方式；而策略参数（阈值、预算）可以后调。
