# 视觉规范

更新：2026-10-28。本文是**参考基线**，不是门禁。产品行为与验收状态见
[当前实现与验收状态](../当前实现与验收状态.md)，执行顺序见[实现计划](../实现计划.md)。
令牌源码位置是 [`app.css`](../../src/litprism/web/static/app.css)。

## 这套规范怎么用

分三层，约束强度不同：

| 层级 | 内容 | 强度 |
|---|---|---|
| 事实约束 | 令牌取值、对比度、布局尺寸 | 改了就重算，别凭感觉 |
| 经验约束 | 组件写法、常见坑 | 默认照做；有明确理由可以偏离，在提交信息里写清理由 |
| 审美判断 | 留白多少、圆角大小、强调方式 | 你来定 |

初版把"常见坑"写成了禁用清单，实践下来过严：界面整体已经可行，
真正缺的是展示效果而不是再收紧规则。现在按上表分层，避免为了合规牺牲表现力。

## 主题体系

四套外观，**只有 `data-theme` 一个属性**，值就是主题 id：

| id | 名称 | 明暗 | 取向 |
|---|---|---|---|
| `paper` | 纸张 | 浅 | 暖中性底 + 深林绿，默认 |
| `paper-dark` | 纸张深色 | 深 | 同配色夜间版 |
| `minimal` | 极简深色 | 深 | 近黑中性灰 + 冷紫蓝，Linear / VS Code |
| `glass` | 毛玻璃 | 浅 | 半透明面板 + 背景模糊，macOS / Fluent |

**明暗不再单独成属性**。早期用 `data-theme`（明暗）+ `data-skin`（风格）两套表述，
结果是"同一个主题被拆成两个地方各说一半"，判断某个样式属于哪套主题要看两处。
现在需要按明暗批量命中时，CSS 里显式列出：

```css
:is([data-theme="paper-dark"], [data-theme="minimal"]) { /* 深色 */ }
```

旧版本只存 `light` / `dark`，`readTheme()` 读到时自动迁移为 `paper` / `paper-dark`。

### 新增一套主题

1. 在 `app.js` 的 `THEMES` 加一项（id / label / desc / swatch）；不再有 palette / skin 字段。
2. 在 `app.css` 用 `[data-theme="<新 id>"]` 写令牌块；深色主题要同时加进每个 `:is(...)` 列表。
3. 在 `desktop-electron/main.js` 的 `TITLEBAR_COLORS` 加同名键（color / symbol / bg），否则标题栏会退回 paper 配色。
4. 跑 `check_workflows --suite workflows`（主题步骤断言 id）并出图目检。

切换入口只有一处：设置 → 通用 → 主题卡（四张，带三色预览与说明）。
标题栏原有的循环按钮已移除——四套主题用循环控件要连点才能到位，控件形状与选项数量不匹配。

### 对比度（实测，AA 要求正文 ≥4.5:1）

| 组合 | paper 浅 | paper 深 | minimal | glass |
|---|---|---|---|---|
| `--text` / `--bg` | 16.08 | 15.79 | 16.26 | 15.01 |
| `--text-2` / `--bg` | 8.75 | 10.39 | 8.30 | 7.09 |
| `--muted` / `--bg` | 5.56 | 6.92 | 5.21 | 4.91 |
| `--muted` / `--panel-2` | 5.22 | 5.84 | 4.64 | — |
| `--accent` / `--panel` | 7.13 | 7.81 | 6.11 | 5.94 |
| 主按钮文字 / `--accent` | 7.13 | 8.36 | 6.49 | 6.49 |

毛玻璃按实际合成底 `#f2f5fa` 计算。新增或调整颜色时重算这几组；
`--muted` 在浅色底上曾为 `#86807a`（3.9:1，不达标），已提升，不要调回去。

## 组件写法

| 组件 | 约定 |
|---|---|
| 主按钮 | `--accent` 底 + 反色文字；hover 用 `--accent-hover`，**同时重申文字色** |
| 次按钮 | `--panel` 底 + `--border` 描边；hover 换 `--panel-2` 底 |
| 危险操作 | `--danger` 文字与描边，hover 用 `--danger-soft` 底；不与主按钮同权重并排 |
| 卡片 | `--panel` 底 + 1px `--border` + `--radius`；卡片内不再套卡片 |
| 折叠头 | 自绘 chevron（`::before` 三角 + `[open]` 旋转 90°） |
| 空状态 | `emptyState()`：图标方块 + 标题 + 一句说明 + 可选动作；卡片内用 `bare` |
| 解读状态条 | 阻断一条（`data-level="block"`）+ 其余折叠；只有提示时整行收起 |
| callout | 1px 整圈描边 + 底色，变体只改 `border-color` / `background` |
| 引用块 | `--accent-soft` 底 + 1px `--accent-line` 描边 |

## 踩过的坑

这些是真实发生过的，不是风格偏好。偏离可以，知道代价就行。

| 坑 | 现象 | 建议 |
|---|---|---|
| hover 只改背景不改文字色 | 被更具体的 `:hover` 改了 `color`，深底上出现近黑文字（实测 1.9:1） | hover 规则里重申 `color` |
| 原生 `<summary>` 三角 | 画在内容盒外，父级内边距 12–14px 时压住边框 | 自绘 chevron |
| 单侧粗色条（`>1px` 彩色 `border-left`） | 与圆角容器脱节，读成"旁边多一条线"；2026-10-28 外部优化包一次引入 5 处 | 想强调就用整圈描边 + 底色，或加粗字重 / 图标 |
| Unicode 字形 / emoji 当图标 | 字重与基线不受控，跨平台不一致 | 本地 SVG（`icon()`，统一 1.6 描边） |
| 标题上方压 eyebrow / kicker | 与标题争夺层级 | 让标题直接说话 |
| 固定 `height` + 纵向 0 内边距 | 文字贴住容器上下边 | `min-height` + 纵向内边距 |
| 长名单全列 | 31 位作者在 390px 下占 14 行，把正文全挤出首屏 | `authorLine()` 折叠，完整名单进 `title` |
| 小字号 | 正文 <12px、控件文字 <11px 时明显吃力 | 正文 ≥12px，控件 ≥11px |

### 触控目标

按输入方式分档，不强求全站 44px（那会让 390px 侧栏一屏少显示 4 项）：

| 场景 | 最小高度 |
|---|---|
| 鼠标为主（桌面宽屏） | 28px 可接受，32px 更稳 |
| 窄屏 / 触屏（≤760px 或 `pointer: coarse`） | 44px |

当前 390px 实测有 25 个控件低于 32px（最差是会话菜单 `⋯` 的 22px）。
已实现 44px 的只有流式停止按钮；其余按实际使用反馈再补，不一次性全改。
