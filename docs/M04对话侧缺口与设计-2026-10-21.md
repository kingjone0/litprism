# M04 对话侧缺口与设计

## 一句话结论

对话侧**主干是通的**（范围、检索、引用、拒答、来源回看、来源入知识库都在），
但它是全项目里**验证最薄**的一环：核心 210 行、1 个测试文件 5 个用例、
N04 验收从未执行。缺口不在"没有功能"，而在**看不见范围、改不了范围、没有尺子**。

## 一、先纠正三个容易搞错的现状

写这份文档时我自己先误判了两次，记下来免得后面重复：

| 误判 | 实际 |
|---|---|
| "界面没接文献范围" | **有**。`workflows.js:214` 新建对话时可选：全部可引用文献 / 知识库勾选的文献 / 单篇 / 分组；后端 `server.py:546-553` 从会话 `scope` 读取，`scope.py:paper_scope` 校验"不存在或已删除不得静默扩为全库" |
| "没有把回答加入知识库的入口" | **有，但入口在来源上不在回答上**：回答底部 `app.js:1082` 渲染 `source_links` → 点击 `workflows.js:615` 打开右栏 → `workflows.js:590`「确认可信并加入知识库」。论文本身已可引用，所以该按钮只对网页/知识条目出现 |
| "chat 只要答对就行" | 不是。回答是模型生成物，**直接入知识库会把生成文本洗成事实**；现在入库的是经人工审核的**来源快照**，这个设计是对的，不该改 |

## 二、缺口 1：范围可设、不可见、不可改 —— ✅ 已实现（2026-10-21）

### 落地记录

| 项 | 实现 |
|---|---|
| 后端 | 合并进既有 `PATCH /api/conversations/{cid}`（`web/workflows.py`，原本只管改名/置顶），新增 `scope` 字段；校验复用 `scope.py:paper_scope` |
| 前端 | 对话页位置条旁新增范围胶囊（`#scopeChip`），显示「全部可引用 / 单篇标题 / N 篇文献 / 分组：xxx」，点击弹窗修改 |
| 快捷入口 | 论文详情页「就这篇提问」→ 新建只含本片的对话（不改现有会话，避免历史回答与新范围不一致） |
| 测试 | `tests/test_chat_scope.py` **10 项**：改范围后证据只来自新范围、清空回到全部、历史保留、未知/已删除文献 409、空列表不等于全部、分组范围、非法形状、改名与范围互不覆盖 |

**为什么合并而不是新开路由**：`workflows.py` 里已有一个 `PATCH /api/conversations/{cid}`（改名/置顶），
我在 `server.py` 新加的同路径路由会把它**整个遮住** —— 第一次跑全量就红了
（`test_gap_filling.py::test_conversation_search_pin_and_bulk_reverification`）。
同一个资源只应有一个更新入口。

### 顺带修掉一个 N12 引入的回归

验证时补录报「原文块与当前分析的材料版本不一致」。原因不是本次改动：
`manual_claims.validate` 拿 `analysis.material_id` 与 chunk 的 `material_id` 比对，
而 **v12 之前的分析 `material_id` 为空**、chunks 已被迁移回填 ——
于是所有历史论文的补录**一律失败**。已改为「只在分析确实绑定了材料时才比对」，
并加回归测试 `test_legacy_analysis_without_material_allows_claim`。

### 原始缺口描述（保留）

### 现状证据

| 项 | 现状 |
|---|---|
| 设定 | 仅在建会话时（`workflows.js:218`），之后无法修改 |
| 修改接口 | **不存在**：`/api/conversations` 只有 GET/POST/DELETE（`server.py:441-450`），无 PUT/PATCH |
| 可见性 | 对话页**不显示**当前范围；`app.js` 里 `scope` 只出现在表格 `scope="col"` |
| 快速限定 | 无"就当前打开的这篇问"的入口 |

### 影响

用户问完才发现答案来自全库，或者想加一篇新导入的论文必须**重建会话**（历史对话丢失）。
这是**每一次提问都受影响**的问题，但改动量最小。

### 最小改动

1. `PATCH /api/conversations/{cid}`：接受 `scope`，复用 `paper_scope()` 校验；
2. 对话页顶部（位置条旁）显示范围胶囊：`全部可引用` / `3 篇` / `分组：xxx`，点击可改；
3. 论文详情页加「就这篇提问」→ 新建或改当前会话范围。

### 验收标准

1. 改范围后，同一问题的引用**只来自新范围**；
2. 范围含已删除论文时明确报错，不静默扩为全库（沿用 `scope.py` 既有语义）；
3. 对话页任何时刻都能看出"这次基于哪些文献"。

## 三、缺口 2：没有尺子（N04）—— ✅ 已实现 2026-10-21

落地：`tools/chat_acceptance.py` + `tools/chat_cases.json`（6 题）+ `tests/test_chat_acceptance.py`（15 项）。
支持 `--mode stub|live` 与 `--sweep`（只扫检索阈值，不调模型）。结果见第九节。

### 现状证据

- 对话侧测试：`tests/test_chat_context.py` **1 个文件、5 个用例**；
- 对照：补录 20 项、质量面板 19 项；
- 真实服务验收：N02 做了四次付费实跑，对话侧**一次都没有**；
- 指标：质量面板只覆盖解读，对话侧无任何指标。

### 影响

改了指代、检索、范围之后，**无法判断是变好还是变坏**。

### 需要先定义的指标

| 指标 | 定义 | 采集方式 |
|---|---|---|
| 引用命中率 | 回答的 `[P#]` 中，能对上真实片段的占比 | 已有 `strict_citation_check`，落库统计 |
| 拒答正确率 | 无证据时是否拒答 / 有证据时是否误拒 | 固定问题集，人工判定 |
| 范围遵守率 | 引用是否全部落在会话范围内 | 结构检查，可自动化 |
| 追问可用率 | 多轮中第二问起是否仍指向正确对象 | 固定多轮脚本 + 人工判定 |

### 最小改动

`tools/chat_acceptance.py`：固定问题集（含正例、应拒答例、多轮追问、跨论文综合），
跑完输出上述四项 + 逐题记录。**先有脚本再有优化**，否则优化无从判断。

### 验收标准

1. 同一份问题集可重复执行，结果可对比；
2. 每项指标带分母；未采集显示 `n/a` 而不是 0；
3. 拒答与"答错"分开统计 —— 拒答是安全行为，答错才是缺陷。

## 四、缺口 3：指代消解是正则拼接

### 现状证据

`context/dialogue.py:28`：

```python
if not re.search(r"这(?:篇|些|个|种)|它(?:们)?|上述|前面|刚才|继续|那(?:篇|些|个)|\b(it|they|...)\b", question):
    return question
for msg in reversed(self.history):
    ...
    return f"{msg['content'][:600]}\n{question}"
```

命中关键词就把**上一个问题整段拼在前面**，不做改写、不判断主语。

### 影响

- "那它的局限呢" → 拼上前一问，可能指向错误对象；
- "继续" → 拼上前一问，但用户想继续的是**上一个回答**的某条，不是重问；
- 换主语（"换个角度，BERT 呢"）→ 正则不命中，历史完全不参与，反而可能丢上下文。

### 最小改动

在 `DialogueContext.query()` 里改为一次**轻量改写调用**（只在检测到指代时触发，不是每问都调）：

```
输入：最近 2 轮对话 + 当前问题
输出：自足的问题（保留原意，补全指代），不超过 120 字
```

失败或超预算时**回退到现有正则拼接**，不阻塞提问。

### 验收标准

1. 固定 10 组多轮脚本（指代 / 继续 / 换主语 / 跨论文），改写后检索命中正确论文的比例可测；
2. 改写调用失败时仍能回答（回退路径有测试）；
3. 改写不得引入新事实（只做指代补全，输出与问题语义等价）。

## 五、缺口 4：检索是单次 BM25

### 现状证据

`search.py:search_local`：BM25 一次检索，`top_k` 默认 8，`min_score` 过滤，
跨语言查询扩展（中↔英）。**无 rerank、无多跳、无章节导航**。

### 影响

- "这篇和 BERT 的区别"需要跨章节取证，top_k=8 容易只捞到零散句子；
- 长论文里同一概念分散在多节时，单次检索按分数截断会漏；
- 已在 [M04](modules/04-检索问答与研究.md) 记为"词法召回可能不足"。

**2026-10-21 实测补充**：跨论文问题 8 条引用全落一篇（无多样性控制）；
且无关问题（"火星上的实验"）的 BM25 最高分 **10.5** 高于正常问题的 **9.66** ——
**分数不可用于区分相关性**，详见第九节。

### 最小改动（按性价比排序）

1. **章节感知召回**：检索命中后，按 `chunks.section` 补足**同章节相邻块**（已有 `section_role`，v13 已具备）；
2. **候选扩充 + rerank**：`top_k × 3` 召回，用模型对"是否直接回答该问题"打分后取前 8；
3. 多跳（问题拆成子问题再合并）**放最后**，成本最高、收益最不确定。

### 验收标准

1. 用 N04 的问题集对比改动前后：引用命中率不下降，跨章节综合题的正确率上升；
2. 每次改动都要报告**调用数与 token**，不能只报质量提升；
3. 章节补足不得跨越论文边界。

## 七、明确不做

| 项 | 理由 |
|---|---|
| **选中原文提问** | 服务少数交互，而范围/指代/检索影响每一次提问；用户可直接在问题里引用原句。触发条件设为"用户抱怨每次都要复制粘贴"，之前视为伪需求 |
| 把**回答**存为知识 | 回答是模型生成物，入知识库等于把生成文本洗成事实；现有"来源→人工审核→入库"是对的路径 |
| 逐 token 流式 | 独立议题（N10），与本次四项无关 |
| 本地 embedding / 向量库 | 与既有决策一致：词法方案没有可复现缺口前不引入 |
| 对话侧语义复核 | 对话回答不进入六字段保证范围，不套用解读的逐条语义标准 |

---

## 八、口径纪律（对话侧）

1. 拒答 ≠ 答错：拒答是安全行为，单独统计；
2. 引用命中 ≠ 内容正确：`strict_citation_check` 只证明引用指向真实片段；
3. 范围遵守可自动化，语义正确不能；
4. 未采集的指标一律 `n/a`，不写 0；
5. 任何"更好了"的结论必须同时给质量与成本（调用数、token）。

## 九、验收结果与处理决定（2026-10-21）

工具：`tools/chat_acceptance.py`，问题集 `tools/chat_cases.json`（6 题：3 应答题 / 2 应拒答 / 1 追问 / 1 跨论文）。

```bash
# 度量管道（桩模式，不花钱）
$PY tools/chat_acceptance.py --home <隔离库目录>
# 真实模型基线（需确认，会花钱）
$PY tools/chat_acceptance.py --home <目录> --mode live --yes
# 只扫检索阈值，不调模型
$PY tools/chat_acceptance.py --home <目录> --sweep 0,2,5,8,10,15
```

### 基线（桩模式，只验证度量管道）

调用失败 0/6；引用命中 48/48；范围遵守 6/6；追问可用 1/1。
拒答 0/2、跨论文 0/1 —— 桩模型永不拒答、只引第一篇，这两项在桩模式下**无意义**，
保留是为了验证度量能正确归零。

### 发现一：拒答问题也拿到满额证据（8 条）

`c3`「火星上的实验」、`c4`「2026 诺贝尔奖得主」都检索到 8 个片段。
根因不在提示词 —— `prompts.py:QA_SYSTEM` 已明确要求"片段不足必须拒答"；
而在检索层 `min_score` 默认 **0.0**（等于不过滤），且词法分无法区分无关与弱相关。

### 发现二：跨论文问题只引到 1 篇

`c6`「这些论文分别研究了什么问题」库里 3 篇均可引用，8 条引用全落同一篇。
`top_k` 没有多样性控制。

### 阈值扫描（不调模型，走生产检索路径）

| min_score | 应拒答题均命中 | 应答题均命中 | 可分 |
|---|---|---|---|
| 0.0 | 8.0 | 8.0 | 否 |
| 5.0 | 6.5 | 8.0 | 否 |
| 8.0 | 2.0 | **1.0** | 否 |
| 10.0 | 0.5 | **0.0** | 否 |
| 15.0 | 0.0 | 0.0 | 否 |

**应拒答题最高分 10.5 ｜ 应答题最高分 9.66** —— 分数**无序**。
在 8.0 处应拒答题留 2 条、应答题只剩 1 条：阈值先杀的是正常问题。

> ⭐ **结论：调 `min_score` 不是杠杆。** 任何绝对阈值都会先误杀应答题，
> 因为无关问题的 BM25 分反而更高（查询里全是"这篇论文/实验/结果"这类高频词）。

### 处理决定

| 问题 | 决定 | 理由 |
|---|---|---|
| 跨论文偏科 | **先做配额**：范围内 ≥2 篇时，先保证每篇至少 1 条，再按分数补足 | 纯增益、无副作用，与阈值无关 |
| 拒答噪声 | **做窄版 rerank**：只判"该片段能否回答该问题"，过滤后仍为空则拒答 | 阈值已被数据否定；rerank 同时缓解跨论文偏科（选取时可控多样性） |
| 指代改写 | 保持原顺序，排在 rerank 之后 | rerank 收益覆盖更广 |
| 多跳 | 不做 | 成本最高、收益最不确定 |

### 明确不做

- **不调 `min_score`**：实测会误杀应答题（见上表）。
- **不加关键词黑名单**：不可维护，换个说法就绕过。
- **不把桩模式数字当质量结论**：桩必然引用第一段，引用命中率恒为 100%。

## 十、下一步修改计划

前置：**改之前先用 live 模式跑一次基线**。桩模式测不出拒答（桩永不拒答），
所以 P2 的效果必须拿真实模型的前后对比说话。一次 live 跑 = 6 题 × 2 次调用（检索扩展 + 回答），
预算很小，但需要你确认。

### P1 跨论文配额（先做，无副作用）

| 项 | 内容 |
|---|---|
| 改哪里 | `search.py:search_local` 的 `finish()` —— 它在截断前能看到全部分数与论文归属 |
| 触发条件 | 范围内可引用论文 ≥2 篇，且命中已覆盖 ≥2 篇 |
| 算法 | 先按论文分组，每篇取最高分 1 条占前 N 席；剩余席位按全局分数补，跳过已选 |
| 不改什么 | 单篇范围、范围为空（全库）时保持现状；`top_k` 语义不变 |
| 风险 | 可能挤掉同篇的高分证据 → 只在多篇时启用，且只占 N 席不独占 |
| 验收 | `c6` 的 `papers` 数 ≥2；`c1/c5` 引用数与引用命中率不降 |
| 预估 | 小改动，可当天完成并验证 |

### P2 窄版 rerank（解决拒答噪声）

| 项 | 内容 |
|---|---|
| 改哪里 | 新增 `search.rerank_hits(kb, question, hits, llm, cfg)`；在 `QAAgent.ask` 取到候选后、组装消息前调用 |
| 候选 | `top_k × 3`（默认 24 条），只取每条前 300 字做摘要，不送全文 |
| 判据 | 只问"这条片段是否包含回答该问题所需的信息"，**不判答案对不对**；输出 `{"keep": [编号…]}` |
| 调用 | 一次批量调用，不是每条一次；失败或格式不合法时**原样返回候选**（不因 rerank 失败而答不出） |
| 全空 | 返回 `[]`，走 `QAAgent` 既有的"零命中 → 拒答"路径，不再把噪声交给生成模型 |
| 成本 | 每题 +1 次调用，输入 ≈ 24 条摘要；缓存可复用前缀 |
| 验收 | `c3/c4` 引用数 8 → 0、拒答正确率 0/2 → 2/2；`c1/c5` 引用数不降；每题调用数 +1 并如实报告 |
| 风险 | 判得过严会误杀 → 先看 `c1/c5` 是否掉；若掉，改为"保留最低 N 条"而不是"全否即拒" |

### 可证伪的预期

改完后同一问题集应出现：

| 指标 | 现在（桩） | 预期（live 改后） |
|---|---|---|
| 拒答正确率 | 0/2 | 2/2 |
| 跨论文引用 | 0/1 | 1/1 |
| 引用命中率 | 100%（桩） | ≥90%（真实模型会写错编号） |
| 每题调用数 | 1 | 2 |

**如果改完拒答仍是 0/2**，说明问题不在检索而在生成层（模型倾向硬答），
那时才去动提示词或加"必须引用具体片段才允许作答"的硬约束 —— 不要反过来先改提示词。

### 顺序与依赖

```
live 基线 → P1 配额 → P2 rerank → 重跑 N04 对比 → 再决定要不要做指代改写
```
